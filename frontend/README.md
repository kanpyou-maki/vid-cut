# vid-cut frontend

編集 UI（TypeScript + React + Vite）。構成は [ARCHITECTURE.md](../ARCHITECTURE.md) と [Design Doc](../docs/design.md) を参照。

```bash
npm install
npm run dev        # 開発サーバー（/api は backend の 127.0.0.1:8765 へ転送）
npm test           # テスト（vitest）
npm run coverage   # カバレッジ（80% 未満で失敗）
npm run typecheck  # 型チェック
npm run lint       # Biome（lint + フォーマット確認）と、API の型が最新かの確認
npm run build      # 本番用のビルド（dist/。`vidcut serve` が配信する）
npm run gen:api    # backend の OpenAPI から API の型を作り直す（src/api/generated/）
```

開発中は、backend を `uv run --directory ../backend vidcut serve --dev` で起動してから `npm run dev` を使い、`http://localhost:5173/` を開く。

- API はトークン（`X-VidCut-Token`）を求める。開発中は Vite のプラグイン（`vite-plugins/devToken.ts`）が、HTML を返すたびに backend の画面の HTML からトークンを読んで埋め込む（[ADR-006](../docs/adr/ADR-006-frontend-foundation.md)）
- 画面に「トークンを読み取れませんでした」と出たら、backend が起動していない。起動してから読み込み直す
- backend を起動し直すとトークンが変わる。「トークンが正しくありません」と出たら読み込み直す
- 5173 番が使われていると、開発サーバーは起動しない（backend は 5173 番のオリジンだけを受け付ける）

## 構成

| フォルダ        | 中身                                                                                |
| --------------- | ----------------------------------------------------------------------------------- |
| `src/app/`      | 画面の枠（見出し、パスに応じた画面の出し分け）                                      |
| `src/library/`  | 素材一覧（`/`）。一覧、投入ダイアログ、まとめる・並べ替え・解除、失敗の再実行       |
| `src/editor/`   | 編集画面（`/lectures/{id}`）。3 ペインの枠、文字起こしの編集、undo / redo、自動保存 |
| `src/shared/`   | 画面をまたいで使う部品（画面の切り替え、ポーリング、ダイアログ）                    |
| `src/api/`      | API クライアント（画面は `Api` のインターフェースだけを使う）、トークン、失敗の種類 |
| `vite-plugins/` | 開発サーバー用のプラグイン                                                          |

依存の向きは `app → library・editor → shared → api`。

画面の実装で守ること（[Design Doc](../docs/design.md) 3-5-1・3-6）:

- トークンは meta 要素から読み、API クライアントの中だけで持つ。`localStorage`・URL・ログに残さない
- `dangerouslySetInnerHTML` を使わない（判定の理由やファイル名は、React の通常の描画で表示する）
- 外部の CDN・フォント・画像を使わない（CSP は `default-src 'self'`）
- 画面に出す失敗の文は `errorMessage`（`src/api/errors.ts`）を通す（例外の文をそのまま出さない）
- ダイアログは `Modal`（`src/shared/Modal.tsx`。`dialog` 要素の `showModal`）を使う。jsdom は `showModal` を持たないので、テストでは `src/test/setup.ts` の代わりの実装が働く
- 一覧を変える操作のあとは、`usePolling` の `refresh` ですぐに読み直す
- 編集状態は不変のオブジェクトとして扱う（`src/editor/edits.ts` の操作は、新しい編集状態を返す）。自動保存は、保存済みと同じオブジェクトかどうかで未保存を判断する
- `Transcript.tsx` と `transcript.ts` のように、大文字と小文字だけが違うファイル名を同じフォルダに置かない（macOS では同じファイルとして扱われ、読み込みを取り違える）

`src/api/generated/` は生成物（`openapi.json` と `schema.d.ts`）。手で編集せず、backend の API を変えたら `npm run gen:api` で作り直してコミットする。
`openapi-typescript` 7 は peer 依存が TypeScript 5 のため、`package.json` の `overrides` でこのプロジェクトの TypeScript 6 を使わせている（TypeScript 6 で生成と型チェックが通ることを確認済み）。

## 手で確かめる（M7 の PR 1: 土台）

実データを書き換えないよう、ワークスペースの写し（`cp -R ~/VidCut ~/VidCut-check`）で行う。コマンドはリポジトリのルートで実行する。

**1. 開発中（Vite の開発サーバー）**

```bash
VIDCUT_WORKSPACE=~/VidCut-check uv run --directory backend vidcut serve --dev   # ターミナル 1
npm --prefix frontend run dev                                                   # ターミナル 2
```

http://localhost:5173/ を開いて確かめる。

- 素材一覧に `s05-12sample`（編集待ち）が出る
- 名前をクリックすると編集画面に移り（PR 1 の時点では「準備中」とだけ出ていた。いまは文字起こしが出る）、「素材一覧へ戻る」とブラウザの「戻る」で一覧に戻る。編集画面で読み込み直しても、編集画面のまま
- ターミナル 1 を Ctrl+C で止めると、1〜2 秒で「サーバーに接続できません」と出る（一覧は残る）
- ターミナル 1 を起動し直すと「トークンが正しくありません。ページを読み込み直してください」と出て、読み込み直すと直る

**2. 本番（ビルドした画面を backend が配信する）**

```bash
npm --prefix frontend run build
VIDCUT_WORKSPACE=~/VidCut-check uv run --directory backend vidcut serve
```

http://127.0.0.1:8765/ を開いて、1 と同じ一覧が出ることを確かめる。開発者ツールで次も確かめる。

- コンソールに CSP の違反（`Content Security Policy` を含むエラー）が出ていない
- Application → Local Storage / Session Storage が空（トークンを保存していない）

確かめたあとは、サーバーを Ctrl+C で止め、`pgrep -fl "vidcut.cli"` で残りがないことを確かめる。

## 手で確かめる（M7 の PR 2: 素材一覧）

実データを書き換えないよう、ワークスペースの写しと、検証素材から切り出した短い動画で行う。コマンドはリポジトリのルートで実行する。

**準備**（前回の `~/VidCut-check` や `~/vidcut-check-clips` が残っていたら、先に消す。残っていると、写しがその中に入れ子で作られる）

```bash
cp -R ~/VidCut ~/VidCut-check
mkdir -p ~/vidcut-check-clips/sub
for i in 1 2 3; do
  ffmpeg -v error -ss $(( (i - 1) * 20 )) -t 20 -i ~/Desktop/s05-12sample.mov -c copy ~/vidcut-check-clips/part$i.mov
done
npm --prefix frontend run build
VIDCUT_WORKSPACE=~/VidCut-check uv run --directory backend vidcut serve
```

http://127.0.0.1:8765/ を開いて、順に確かめる。

**1. 一覧と投入**

- 一覧に `s05-12sample`（編集待ち）が出て、右に本数と合計時間（`1 本・…`）が出る
- 「投入…」でダイアログが開く。ホームから始まり、フォルダ名（末尾に `/`）を押すと中へ移動する。「上へ」「ホーム」で戻れる（ホームでは「上へ」を押せない）
- `vidcut-check-clips` に入ると、`sub/` と `part1.mov`〜`part3.mov` が出る。Esc か「キャンセル」で閉じ、もう一度「投入…」を押すと、同じフォルダから始まる
- 「すべて選ぶ」で 3 件にチェックが入り、ボタンが「投入（3 件）」になる。`sub/` に入って戻ると、チェックは消えている
- 3 件を選んで「投入（3 件）」を押したら、**すぐに**別のターミナルで `rm ~/vidcut-check-clips/part3.mov` を実行する（あとで失敗の表示を確かめる）
- ダイアログが閉じ、一覧の上に「投入の結果: 追加 3 件・登録済み 0 件・失敗 0 件」と出る。「閉じる」で消える
- `part1`・`part2` の状態が、待機中 → 解析中 n% → 判定中 → 編集待ち と変わる（読み込み直さなくてよい）
- もう一度 `part1.mov` を投入すると「追加 0 件・登録済み 1 件・失敗 0 件」と出る

**2. 失敗と再実行**

- `part3` が「失敗」になり、行の下に「解析（part3.mov）: 録画ファイルが見つかりません。…」と「再実行」が出る
- 動画を作り直してから（`ffmpeg -v error -ss 40 -t 20 -i ~/Desktop/s05-12sample.mov -c copy ~/vidcut-check-clips/part3.mov`）「再実行」を押すと、解析が進んで「編集待ち」になる

**3. まとめる・並べ替え・解除**

- チェックが 1 件以下のときは「まとめる」を押せない。`part2`、`part1` の順にチェックすると「まとめる（2 件）」になる
- 押すと、題名の初期値が `part1`（一覧で上にあるほう）のダイアログが開き、まとめる順番が `part1.mov`、`part2.mov` と出る。題名を空にすると「まとめる」を押せない
- 題名を入れて「まとめる」を押すと、2 つのレクチャーが 1 つになり（`2 本・…`）、録画ファイルが番号付きで出る。判定がやり直される（判定中 → 編集待ち）。チェックは外れている
- 録画ファイルの ↑ ↓ を押すと、順番が入れ替わる（先頭の ↑ と末尾の ↓ は押せない）。判定がやり直される
- 「解除」を押すと確認が出る。「キャンセル」と Esc では何も起きない。「解除する」で、録画ファイルごとのレクチャー（題名はファイル名）に戻る

**4. 失敗の表示（サーバーを止める）**

- サーバーを Ctrl+C で止めると、1〜2 秒で「サーバーに接続できません」と出る（一覧は残る）。その状態で ↑ ↓ や「再実行」を押しても、同じ文が出るだけで画面は壊れない

開発者ツールで次も確かめる。

- コンソールに CSP の違反（`Content Security Policy` を含むエラー）が出ていない
- Application → Local Storage / Session Storage が空

確かめたあとは、サーバーを Ctrl+C で止め、`pgrep -fl "vidcut.cli"` で残りがないことを確かめて、`rm -rf ~/VidCut-check ~/vidcut-check-clips` で片付ける。

## 手で確かめる（M7 の PR 3: 編集状態と文字起こしの基本）

実データを書き換えないよう、ワークスペースの写しで行う。コマンドはリポジトリのルートで実行する。
PR 4 で変わった表示（凡例の項目、候補に重ねたときの表示、戻した候補の見え方）は、いまの挙動に合わせて書き直してある。

**準備**（前回の `~/VidCut-check` が残っていたら、先に消す）

```bash
cp -R ~/VidCut ~/VidCut-check
npm --prefix frontend run build
VIDCUT_WORKSPACE=~/VidCut-check uv run --directory backend vidcut serve
```

http://127.0.0.1:8765/ を開いて、順に確かめる。

**1. 開く・配置**

- 一覧の `s05-12sample` を押すと編集画面に移る。上の行に「素材一覧へ戻る」・題名・「保存済み」・「削除」「元に戻す」「やり直す」（3 つとも押せない）が出る
- 左にプレビュー（準備中）、右に文字起こし、下に波形（準備中）が出る。縦にスクロールするのは文字起こしだけで、ページ全体はスクロールしない
- 文字起こしは、段落ごとに左に開始時刻（`0:08` など）が出る。上に凡例（言い直し・言い間違い・雑音・フィラー・手動・戻し済み・要確認）が出る
- 言い直しの候補（赤い背景と取り消し線）が出ている。重ねると、近くに種類と理由が出る
- ウィンドウの幅を 900px 以下にすると、プレビュー・文字起こし・波形が縦に積まれ、ページ全体がスクロールする

**2. 選択 → 削除**

- 文字をドラッグで選ぶと「削除」を押せるようになる。Delete（または Backspace）を押すと、選んだ文字がグレーの背景と取り消し線になり、選択が外れる
- 上の行が「未保存の変更があります」になり、約 1 秒後に「保存中…」を経て「保存済み」に戻る
- 段落をまたいで選んで「削除」ボタンを押しても、同じように削除される（押したときに選択が外れない）
- 時刻（`0:08` など）は選択に入らない
- 何も選ばずに Delete を押しても、何も起きない

**3. 復活**

- 言い直しの候補（赤）をクリックすると、その候補全体が、破線の下線の「戻し済み」になる（削除されなくなる。もう一度クリックすると、削除に戻る）
- 手動の削除（グレー）をクリックすると、その削除全体が戻る
- Tab で削除済みの部分にフォーカスを移し（枠が付く）、Enter か Space を押しても戻る
- 削除済みの部分の中からドラッグを始めて選択しても、戻らない

**4. undo / redo**

- ⌘Z で直前の操作（削除・復活）が取り消され、⇧⌘Z でやり直される。「元に戻す」「やり直す」のボタンでも同じ
- 最初の状態まで戻すと「元に戻す」を押せなくなる。取り消したあとに別の操作をすると「やり直す」を押せなくなる
- 取り消し・やり直しのあとも、約 1 秒後に「保存済み」になる

**5. 保存と再開（US-08）**

- いくつか編集して「保存済み」になってから読み込み直すと、編集した内容のまま開く（履歴は消えていて「元に戻す」は押せない）
- 編集してすぐ（1 秒たつ前に）「素材一覧へ戻る」を押し、1〜2 秒おいてからもう一度開くと、その編集が残っている
  （間をおかずに開き直すと、離れるときの保存と読み込みが前後して、次の編集で 6 のダイアログが出ることがある。読み込み直せば続けられる）
- 編集してすぐにタブを閉じようとする（または読み込み直そうとする）と、ブラウザの確認が出る

**6. 版の食い違い（409）**

- 同じレクチャーの編集画面を、もう 1 つのタブで開く（タブ A・タブ B）
- タブ A で文字を削除し、「保存済み」になるのを待つ
- タブ B で別の文字を削除すると、約 1 秒後に「編集状態が更新されました」のダイアログが出る。Esc では閉じない
- 「読み込み直す」を押すと、タブ A の内容になる（タブ B で削除した分は消える）。そのあとタブ B で編集すると、普通に保存される

**7. 保存の失敗**

- サーバーを Ctrl+C で止めてから文字を削除すると、約 1 秒後に「保存できませんでした: サーバーに接続できません。…」と「再試行」が出る
- サーバーを起動し直して「再試行」を押すと、「保存できませんでした: トークンが正しくありません。ページを読み込み直してください」に変わる
  （起動し直すとトークンが変わるため。読み込み直すと、保存できていなかった編集は失われる）

**8. 解析・判定が済んでいないレクチャー**（任意。`claude` にログイン済みであること）

```bash
mkdir -p ~/vidcut-check-clips
ffmpeg -v error -t 20 -i ~/Desktop/s05-12sample.mov -c copy ~/vidcut-check-clips/part1.mov
```

- 素材一覧で `part1.mov` を投入し、すぐに `part1` を開くと、文字起こしの代わりに「待機中です。終わると自動で表示されます。」「解析中 n%です。…」と出る
- 解析が終わると、文字起こしが読み取り専用で出て（削除済みの部分を押しても戻らない。上の行にボタンがない）、「判定中です。終わると編集できます。」と出る
- 判定が終わると、読み込み直さなくても編集できるようになる（上の行に「保存済み」とボタンが出る）
- アドレスバーに `http://127.0.0.1:8765/lectures/nonexistent` を入れると、「指定されたデータが見つかりません」のような失敗の文が出る

開発者ツールで次も確かめる。

- コンソールに CSP の違反（`Content Security Policy` を含むエラー）が出ていない（6 の 409 と 7 の接続の失敗は、ネットワークの失敗として出る）
- Application → Local Storage / Session Storage が空

確かめたあとは、サーバーを Ctrl+C で止め、`pgrep -fl "vidcut.cli"` で残りがないことを確かめて、`rm -rf ~/VidCut-check ~/vidcut-check-clips` で片付ける。

## 手で確かめる（M7 の PR 4: 要確認・判定理由・通知）

実データを書き換えないよう、ワークスペースの写しで行う。コマンドはリポジトリのルートで実行する。

**準備**（前回の `~/VidCut-check` が残っていたら、先に消す。2 行目は、通知を確かめるために、引き継げなかった候補を 2 件あったことにする）

```bash
cp -R ~/VidCut ~/VidCut-check
sqlite3 ~/VidCut-check/vidcut.sqlite3 "UPDATE judgements SET dropped_restored_ids = '[\"old-a\", \"old-b\"]'"
npm --prefix frontend run build
VIDCUT_WORKSPACE=~/VidCut-check uv run --directory backend vidcut serve
```

http://127.0.0.1:8765/ を開き、`s05-12sample` の編集画面で、順に確かめる。

**1. 引き継げなかった戻し候補の通知**

- 上のほうに「判定のやり直しで、戻していた候補 2 件を引き継げませんでした。その箇所は、削除の候補に戻っています。」と「閉じる」が出る
- 「閉じる」を押すと消える。読み込み直しても、もう出ない

**2. 要確認の印と移動**

- 文字起こしの上に、凡例（言い直し・言い間違い・雑音・フィラー・手動・戻し済み・要確認）と、「要確認 n 件」「前の要確認へ」「次の要確認へ」が出る。文字起こしをスクロールしても、上に残る
- 確信度が低い文字に、波線の下線が付いている（`5:01` の「1つ目。」など）。重ねると「要確認（確信度が低い）」と出る
- 「次の要確認へ」を押す（または N キー）と、次の要確認の文字が選択されて、見える位置に出る。表示が「要確認 1 / n」のように変わる。Shift+N で前へ戻る。最後の次は最初に戻る
- 選択された状態で Delete を押すと、その文字が削除されて、数が 1 つ減る。続けて N を押すと、その次の箇所へ進む（最初に戻らない）
- 削除済みの部分の中にある波線（言い直しの中など）は、数に入らない

**3. 判定理由**

- 言い直しの候補（赤）にカーソルを合わせると、すぐ下に「言い直し（削除）」・理由・「言い直し先: 0:34」のような時刻・「言い直し先へ移動」が出る
- カーソルをその表示の上へ移しても消えない。「言い直し先へ移動」を押すと、言い直した段落が見える位置に出て、しばらく背景色が付く
- カーソルを外すと、約 0.2 秒後に消える。出ている間に Esc を押すか、文字起こしをスクロールしても消える
- 画面の下のほうにある候補では、表示が上に出る
- 手動の削除（グレー）には出ない（重ねると「手動（クリックで元に戻す）」と出るだけ）
- Tab で候補にフォーカスを移しても、同じ表示が出る（「言い直し先へ移動」は、マウスでだけ押せる）

**4. 採否の切り替え**

- 言い直しの候補をクリックすると、破線の下線の「戻し済み」になる。カーソルを合わせたままなら、表示が「言い直し（戻し済み）」「クリックで削除に戻せます」に変わる
- 戻し済みの部分をもう一度クリックすると、削除（赤い背景と取り消し線）に戻る。Tab で選んで Enter でも同じ
- どちらも、約 1 秒後に「保存済み」になり、⌘Z で取り消せる

開発者ツールで、コンソールに CSP の違反（`Content Security Policy` を含むエラー）が出ていないことも確かめる。

確かめたあとは、サーバーを Ctrl+C で止め、`pgrep -fl "vidcut.cli"` で残りがないことを確かめて、`rm -rf ~/VidCut-check` で片付ける。
