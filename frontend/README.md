# vid-cut frontend

編集 UI（TypeScript + React + Vite）。構成は [ARCHITECTURE.md](../ARCHITECTURE.md) と [Design Doc](../docs/design.md) を参照。

```bash
npm install
npm run dev        # 開発サーバー（/api は backend の 127.0.0.1:8765 へ転送）
npm test           # テスト（vitest）
npm run coverage   # カバレッジ（80% 未満で失敗）
npm run typecheck  # 型チェック
npm run lint       # Biome（lint + フォーマット確認）と、API の型が最新かの確認
npm run build      # 本番用のビルド（dist/。`vidcut serve` が配信する）
npm run gen:api    # backend の OpenAPI から API の型を作り直す（src/api/generated/）
npm run e2e        # E2E（Playwright。画面をビルドし、E2E 用の backend を起動して、Chrome で操作する）
```

開発中は、backend を `uv run --directory ../backend vidcut serve --dev` で起動してから `npm run dev` を使い、`http://localhost:5173/` を開く。

- API はトークン（`X-VidCut-Token`）を求める。開発中は Vite のプラグイン（`vite-plugins/devToken.ts`）が、HTML を返すたびに backend の画面の HTML からトークンを読んで埋め込む（[ADR-006](../docs/adr/ADR-006-frontend-foundation.md)）
- 画面に「トークンを読み取れませんでした」と出たら、backend が起動していない。起動してから読み込み直す
- backend を起動し直すとトークンが変わる。「トークンが正しくありません」と出たら読み込み直す
- 5173 番が使われていると、開発サーバーは起動しない（backend は 5173 番のオリジンだけを受け付ける）

## 構成

| フォルダ        | 中身                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/app/`      | 画面の枠（見出し、パスに応じた画面の出し分け）                                                                                             |
| `src/library/`  | 素材一覧（`/`）。一覧、投入ダイアログ、まとめる・並べ替え・解除、失敗の再実行                                                              |
| `src/editor/`   | 編集画面（`/lectures/{id}`）。3 ペインの枠、文字起こしの編集、undo / redo、自動保存、プレビュー、波形、書き出し                            |
| `src/shared/`   | 画面をまたいで使う部品（画面の切り替え、ポーリング、ダイアログ）                                                                           |
| `src/api/`      | API クライアント（画面は `Api` のインターフェースだけを使う）、トークン、失敗の種類                                                        |
| `vite-plugins/` | 開発サーバー用のプラグイン                                                                                                                 |
| `e2e/`          | E2E（Playwright）。シナリオ（`*.e2e.ts`）、画面の操作（`pages.ts`）、裏で起きた問題の検出（`fixtures.ts`）、舞台の場所と台本（`stage.ts`） |

依存の向きは `app → library・editor → shared → api`。

画面の実装で守ること（[Design Doc](../docs/design.md) 3-5-1・3-6）:

- トークンは meta 要素から読み、API クライアントの中だけで持つ。`localStorage`・URL・ログに残さない
- `dangerouslySetInnerHTML` を使わない（判定の理由やファイル名は、React の通常の描画で表示する）
- 外部の CDN・フォント・画像を使わない（CSP は `default-src 'self'`）
- スタイルは CSS Modules に書く。インラインのスタイル（`style` 要素、`style` 属性の文字列）は CSP が止める。
  要素の `style` に直接書く（React の `style`、`element.style.left = …`）のは止められない
- `wavesurfer.js` を読み込むのは `src/editor/waveChart.ts` だけ。版は固定している（`package.json` の `8.0.1`）。
  wavesurfer.js は Shadow DOM の中に `style` 要素を 1 つ差し込み、CSP はその中身のハッシュだけを許可している。
  版か波形の高さ（`WAVE_HEIGHT_PX`）を変えると `waveChart.test.ts` が落ちるので、出てきたハッシュを
  `backend/tests/api/waveform_style_hash.json` と `backend/src/vidcut/api/headers.py` に書く
- wavesurfer.js は、描き終える（`ready`）まで長さを 0 として扱う。区間・再生位置・拡大率は、`waveChart.ts` が覚えておいて、描き終えてから反映する
- 画面に出す失敗の文は `errorMessage`（`src/api/errors.ts`）を通す（例外の文をそのまま出さない）
- ダイアログは `Modal`（`src/shared/Modal.tsx`。`dialog` 要素の `showModal`）を使う。jsdom は `showModal` を持たないので、テストでは `src/test/setup.ts` の代わりの実装が働く
- 波形のテストは、実物の wavesurfer.js を jsdom で動かす。jsdom にない `matchMedia` と canvas の描画先の代わりは `src/test/setup.ts`、
  大きさ（jsdom は計算しない）と Shadow DOM の中の要素を扱う準備は `src/test/waveform.ts` にある。線と位置の見た目は、実物のブラウザで確かめる
- 一覧を変える操作のあとは、`usePolling` の `refresh` ですぐに読み直す
- 編集画面は、編集できる状態になったあと、レクチャーの詳細を読み直さない。書き出しの状態だけは、待機中か実行中の書き出しがある間、`getExports` で 1 秒ごとに読む（`ExportBar.tsx` の `ExportWatcher`）
- 書き出しを頼む前に、未保存の変更を保存する（`useEditing` の `flushSave`。書き出しのジョブは、保存済みの編集状態を読む）。間の設定（`usePadding` の `flush`）も同じ
- 残す発話の前後の余白は、`usePadding` が持つ値を使う（`useEditing` に渡す）。`detail.keep_padding` は、開いたときの値でしかない
- 保存先のパスは利用者のファイル名に由来する。React の通常の描画で出す。「Finder で開く」は、レクチャーの id だけを送る（開く場所を、画面から送らない）
- ボタンと見出しの文字は、幅が狭くても途中で折り返さないようにする（`white-space: nowrap`。折り返しは、実物のブラウザで幅を狭めて確かめる）
- 挙動や表示を変えたら、[Design Doc](../docs/design.md) の前の節と、このファイルの前の PR の手動確認の手順に、古い記述が残っていないかを確かめて直す
  （変えた文言や機能名で検索する。値や状態の持ち主を移したときは、「持たない」「〜だけ」のような否定・限定の記述も探し、当たった段落は最後まで読む。FRIC-005）
- 編集状態は不変のオブジェクトとして扱う（`src/editor/edits.ts` の操作は、新しい編集状態を返す）。自動保存は、保存済みと同じオブジェクトかどうかで未保存を判断する
- `Transcript.tsx` と `transcript.ts` のように、大文字と小文字だけが違うファイル名を同じフォルダに置かない（macOS では同じファイルとして扱われ、読み込みを取り違える）

`src/api/generated/` は生成物（`openapi.json` と `schema.d.ts`）。手で編集せず、backend の API を変えたら `npm run gen:api` で作り直してコミットする。
`openapi-typescript` 7 は peer 依存が TypeScript 5 のため、`package.json` の `overrides` でこのプロジェクトの TypeScript 6 を使わせている（TypeScript 6 で生成と型チェックが通ることを確認済み）。

## E2E（M8）

`npm run e2e`（リポジトリのルートからは `.claude/harness.json` の `commands.e2e`）。投入 → 解析 → 編集 → 書き出しを、実物の backend と Chrome で通す（[Design Doc](../docs/design.md) 6 章）。20 秒ほどで終わる。

- macOS が前提（取り消しのキーは ⌘Z を送る。アプリ自体も macOS 用）
- 必要なもの: ffmpeg、uv、Google Chrome（Playwright 付属の Chromium は H.264 を再生できないので、入っている Chrome を使う。`npx playwright install` は要らない）
- 流れ: 画面を `e2e/run/dist/` にビルドする（`dist/` は書き換えない）→ Playwright が E2E 用の backend（`backend/tests/e2e/serve.py`）を 8799 番で起動する → Chrome で操作する → backend を止める
- E2E 用の backend は、ML と判定だけを偽の実装に差し替える（結果は、台本 `backend/tests/e2e/script.json` で決まる）。ffmpeg・SQLite・API・worker・書き出しは実物。
  ワークスペースと素材は `e2e/run/stage/` に、実行のたびに作り直す（`~/VidCut` は使わない。環境変数 `VIDCUT_WORKSPACE` も見ない）。「Finder で開く」は、窓を開かずログに出すだけ
- どのテストも、コンソールの失敗（CSP の違反を含む）・失敗した要求・4xx / 5xx の応答が 1 つでもあれば失敗する（`e2e/fixtures.ts`）
- 失敗したときの画面の画像は `e2e/run/results/` に残る。記録（trace）は取らない（要求のヘッダーにトークンが入るため）
- ファイル名は `*.e2e.ts`（vitest は拾わない）。型チェックは `tsconfig.e2e.json`、整形と lint は Biome（ほかと同じ）
- 台本か、残す区間の計算（余白など）を変えたら、`e2e/flow.e2e.ts` の先頭の値（カット後の長さ、余白、残る行）も合わせる
- 8799 番が使われていると起動しない。前回のプロセスが残っていないかは `pgrep -fl "vidcut.cli|tests.e2e"` で確かめる

## 手で確かめる（M8 の PR 3: 間の設定）

`uv run --directory ../backend vidcut serve` で起動し、解析済みのレクチャーを開く（解析のやり直しは要らない）。

1. プレビューの下の「間の設定」を開く。「前」「後ろ」「文の終わりのあと」に、いまの値（最初は 150・250・500）が出る
2. 「文の終わりのあと」を 800 にする → 右の時間（カット後の長さ）がすぐに伸び、少しして「保存済み」になる。「。」で終わる文のあとを再生して、間が長くなったことを聞く
3. 値を変えながら聞き比べる（400・600・800 など）。「前」「後ろ」も同じように試せる
4. 空にする・2001 を入れる → 「0〜2000 の整数で入力してください」と出て、プレビューは変わらない。入力欄の外を押すと、使っている値に戻る
5. 画面を読み込み直す → 変えた値のまま。ほかのレクチャーを開いても、同じ値（ワークスペース全体で 1 組）
6. 値を変えた直後に「Premiere XML」を押す → 書き出した XML が、新しい値のカットになっている（保存してから書き出す）
7. 「既定に戻す」→ 150・250・500 に戻る

決めた値を伝えてもらえれば、それを既定値にする（`backend/src/vidcut/domain/timeline.py` の `DEFAULT_PAD_AFTER_SENTENCE_MS` など）。

## 手で確かめる（M7 の PR 2: 素材一覧）

実データを書き換えないよう、ワークスペースの写しと、検証素材から切り出した短い動画で行う。コマンドはリポジトリのルートで実行する。

**準備**（前回の `~/VidCut-check` や `~/vidcut-check-clips` が残っていたら、先に消す。残っていると、写しがその中に入れ子で作られる）

```bash
cp -R ~/VidCut ~/VidCut-check

for i in 1 2 3; do
  ffmpeg -v error -ss $(( (i - 1) * 20 )) -t 20 -i ~/Desktop/s05-12sample.mov -c copy ~/vidcut-check-clips/part$i.mov

npm --prefix frontend run build
```

http://127.0.0.1:8765/ を開いて、順に確かめる。

**1. 一覧と投入**

- 一覧に `s05-12sample`（編集待ち）が出て、右に本数と合計時間（`1 本・…`）が出る

- `part3` が「失敗」になり、行の下に「解析（part3.mov）: 録画ファイルが見つかりません。…」と「再実行」が出る
- 動画を作り直してから（`ffmpeg -v error -ss 40 -t 20 -i ~/Desktop/s05-12sample.mov -c copy ~/vidcut-check-clips/part3.mov`）「再実行」を押すと、解析が進んで「編集待ち」になる

**3. まとめる・並べ替え・解除**

- チェックが 1 件以下のときは「まとめる」を押せない。`part2`、`part1` の順にチェックすると「まとめる（2 件）」になる

- 題名を入れて「まとめる」を押すと、2 つのレクチャーが 1 つになり（`2 本・…`）、録画ファイルが番号付きで出る。判定がやり直される（判定中 → 編集待ち）。チェックは外れている
- 録画ファイルの ↑ ↓ を押すと、順番が入れ替わる（先頭の ↑ と末尾の ↓ は押せない）。判定がやり直される
- 「解除」を押すと確認が出る。「キャンセル」と Esc では何も起きない。「解除する」で、録画ファイルごとのレクチャー（題名はファイル名）に戻る

**4. 失敗の表示（サーバーを止める）**

- サーバーを Ctrl+C で止めると、1〜2 秒で「サーバーに接続できません」と出る（一覧は残る）。その状態で ↑ ↓ や「再実行」を押しても、同じ文が出るだけで画面は壊れない

- コンソールに CSP の違反（`Content Security Policy` を含むエラー）が出ていない
- Application → Local Storage / Session Storage が空

## 手で確かめる（M7 の PR 3: 編集状態と文字起こしの基本）

実データを書き換えないよう、ワークスペースの写しで行う。コマンドはリポジトリのルートで実行する。
PR 4〜PR 6 で変わった表示（凡例の項目、候補に重ねたときの表示、戻した候補の見え方、プレビュー、波形）は、いまの挙動に合わせて書き直してある。

**準備**（前回の `~/VidCut-check` が残っていたら、先に消す）

```bash
cp -R ~/VidCut ~/VidCut-check
npm --prefix frontend run build
VIDCUT_WORKSPACE=~/VidCut-check uv run --directory backend vidcut serve
```

http://127.0.0.1:8765/ を開いて、順に確かめる。

**1. 開く・配置**

- 一覧の `s05-12sample` を押すと編集画面に移る。上の行に「素材一覧へ戻る」・題名・「保存済み」・「削除」「元に戻す」「やり直す」（3 つとも押せない）が出る。
  そのすぐ下に、書き出しの行（「Premiere XML」「MP4」・保存先・「Finder で開く」）が出る（確かめ方は、PR 7 の手順）
- 左にプレビュー、右に文字起こし、下に波形（録画の波形と、色の付いた削除区間）が出る。縦にスクロールするのは文字起こしだけで、ページ全体はスクロールしない
- 文字起こしは、段落ごとに左に開始時刻（`0:08` など）が出る。上に凡例（言い直し・言い間違い・雑音・フィラー・手動・戻し済み・要確認）が出る
- 言い直しの候補（赤い背景と取り消し線）が出ている。重ねると、近くに種類と理由が出る
- ウィンドウの幅を 900px 以下にすると、プレビュー・文字起こし・波形が縦に積まれ、ページ全体がスクロールする

**2. 選択 → 削除**

- 文字をドラッグで選ぶと「削除」を押せるようになる。Delete（または Backspace）を押すと、選んだ文字がグレーの背景と取り消し線になり、選択が外れる
- 上の行が「未保存の変更があります」になり、約 1 秒後に「保存中…」を経て「保存済み」に戻る
- 段落をまたいで選んで「削除」ボタンを押しても、同じように削除される（押したときに選択が外れない）
- 時刻（`0:08` など）は選択に入らない
- 何も選ばずに Delete を押しても、何も起きない

**3. 復活**

- 言い直しの候補（赤）をクリックすると、その候補全体が、破線の下線の「戻し済み」になる（削除されなくなる。もう一度クリックすると、削除に戻る）
- 手動の削除（グレー）をクリックすると、その削除全体が戻る
- Tab で削除済みの部分にフォーカスを移し（枠が付く）、Enter か Space を押しても戻る
- 削除済みの部分の中からドラッグを始めて選択しても、戻らない

**4. undo / redo**

- ⌘Z で直前の操作（削除・復活）が取り消され、⇧⌘Z でやり直される。「元に戻す」「やり直す」のボタンでも同じ
- 最初の状態まで戻すと「元に戻す」を押せなくなる。取り消したあとに別の操作をすると「やり直す」を押せなくなる
- 取り消し・やり直しのあとも、約 1 秒後に「保存済み」になる

**5. 保存と再開（US-08）**

- いくつか編集して「保存済み」になってから読み込み直すと、編集した内容のまま開く（履歴は消えていて「元に戻す」は押せない）

**9. コンソールと CSP**
