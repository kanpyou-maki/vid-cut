# Skill: sync-upstream — プロジェクト改善をマスターに反映

このプロジェクトで生まれた汎用的な改善を `claude-config-master` へ PR として反映する。
master とこのプロジェクトは `.claude/` 配下が**同型レイアウト**のため、対応ファイルはパス変換なしの 1:1 で比較・コピーできる。

## トリガー

「マスターに改善を反映して」「この改善を上流へ同期して」と言われたとき。
または improve-harness スキルが「この改善は汎用的」と判断したとき。

---

## 手順

### 1. マスターパスを確認する

install.sh がプロジェクトに `.claude/master-path` を書き込んでいる。無ければ `~/.claude/master-path` にフォールバックする。

```bash
MASTER=$(cat .claude/master-path 2>/dev/null || cat ~/.claude/master-path 2>/dev/null || echo "")
if [[ -z "$MASTER" || ! -d "$MASTER" ]]; then
  echo "ERROR: master-path が未設定または無効です"
  echo "設定方法: echo \"/path/to/claude-config-master\" > .claude/master-path"
  exit 1
fi
echo "Master: $MASTER"
```

### 2. 差分を洗い出す

```bash
MASTER=$(cat .claude/master-path 2>/dev/null || cat ~/.claude/master-path)

# .claude/ は同型レイアウトなのでそのまま比較できる
for dir in agents hooks rules skills; do
  echo "=== .claude/$dir vs $MASTER/.claude/$dir ==="
  diff -rq ".claude/$dir/" "$MASTER/.claude/$dir/" 2>/dev/null || true
done

# 配布対象の docs（master の dist-manifest.json の docsSkeleton に列挙されている）
for doc in $(node -e "for (const d of require('$MASTER/dist-manifest.json').docsSkeleton) console.log(d)"); do
  echo "=== $doc ==="
  diff -q "$doc" "$MASTER/$doc" 2>/dev/null || true
done
```

### 3. 汎用性を判断する

差分ファイルごとに次の基準で分類する:

| 条件 | 判断 |
|------|------|
| CLAUDE.md / ARCHITECTURE.md / PROJECT_STATUS.md | **スキップ**（プロジェクト固有）|
| `.claude/harness.json` / `.claude/master-path` / settings.local.json | **スキップ**（プロジェクト固有。manifest の exclude 対象）|
| プロジェクト名・DB名・サービス名を含む | **スキップ** |
| エージェント手順の汎用的改善（特定アプリに依存しない）| 候補 |
| フックの検出精度向上・バグ修正 | 候補 |
| ルール・スキルの追加・改善 | 候補 |
| friction-log で解消した摩擦への恒久対策 | 候補（改善の背景として PR 本文に FRIC-NNN を引用）|

**候補ファイルの一覧を人間に提示して確認を求める。承認後にのみ次へ進む。**

### 4. マスターに反映する

```bash
MASTER=$(cat .claude/master-path 2>/dev/null || cat ~/.claude/master-path)
PROJECT=$(basename "$(pwd)")
BRANCH="improve/from-${PROJECT}-$(date +%Y%m%d)"

cd "$MASTER"
git checkout main && git pull
git checkout -b "$BRANCH"

# 承認されたファイルをコピー（同型レイアウトのためパスは同一）
# cp "<project>/.claude/agents/foo.md" "$MASTER/.claude/agents/foo.md"
# cp "<project>/docs/golden-rules.md"  "$MASTER/docs/golden-rules.md"

# 新しいスキルを追加した場合は dist-manifest.json への登録も忘れないこと
# （登録しないと install.sh が配布しない）

git add -A
git commit -m "$(cat <<EOF
improve: [改善内容の概要]

Synced from $PROJECT

Co-Authored-By: sync-upstream-skill <noreply@anthropic.com>
EOF
)"

gh pr create \
  --title "improve: [改善内容の概要]" \
  --body "$(cat <<EOF
## 改善内容

[説明]

## 反映元

Project: $PROJECT
Date: $(date +%Y-%m-%d)
関連する摩擦: [FRIC-NNN があれば]

🤖 Generated by sync-upstream skill
EOF
)"
```

### 5. master 側の検証

PR 作成前に master のテストが通ることを確認する:

```bash
cd "$MASTER"
bash -c "$(node -pe "require('./.claude/harness.json').commands.test")"
node .claude/hooks/structure-test.js
```

---

## 注意事項

- PR 作成後は必ず人間がレビューして master にマージすること
- 新しいエージェント・スキル・フックを追加する場合は `dist-manifest.json` と master の README / CLAUDE.md のエージェント一覧も更新すること
- マスターへのマージ後は他プロジェクトへの下流同期（sync-downstream / `install.sh update`）を検討する
