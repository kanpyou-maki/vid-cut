# Design Doc: vid-cut MVP

**ステータス:** 承認済み
**作成日:** 2026-10-03
**シーケンス設定:** 元素材の解像度・60fps（2026-10-03 決定）
**関連 PRD:** [docs/prd.md](./prd.md)
**関連 ADR:** [ADR-001](./adr/ADR-001-language-and-stack.md)（言語）、[ADR-002](./adr/ADR-002-vfr-mezzanine.md)（可変フレームレート）、
[ADR-003](./adr/ADR-003-transcription-engine.md)（文字起こし）、[ADR-004](./adr/ADR-004-local-app-runtime.md)（実行形態と永続化）

## 1. 概要

録画ファイルを解析して削除候補を作り、レクチャー単位の編集画面で人が確認・修正し、Premiere XML と MP4 を書き出す。
すべてローカルの 1 台の Mac（Apple Silicon）で動き、利用者は制作者本人 1 名。

処理は 3 つの単位に分かれる。

| 単位         | 処理                                                                      | 再実行の条件                                     |
| ------------ | ------------------------------------------------------------------------- | ------------------------------------------------ |
| 録画ファイル | 検査 → 中間素材の作成 → 無音検出 → 文字起こし → 位置合わせ → フィラー検出 | 元ファイルが変わったとき（通常は 1 回だけ）      |
| レクチャー   | 言い直しの判定（ファイルをまたぐ）                                        | 構成（ファイルの組み合わせ・順序）が変わったとき |
| 書き出し     | 残す区間の計算 → Premiere XML / MP4                                       | 書き出しのたび                                   |

録画ファイル単位の重い処理（ML）と、レクチャー単位の軽い処理（判定）を分けることで、
レクチャーのまとめ方を変えても文字起こしをやり直さずに済む（US-11）。

## 2. アーキテクチャ

```
┌────────────── ブラウザ（frontend: React + Vite） ───────────────┐
│ 素材一覧（投入・進捗・まとめる）     編集画面（3 ペイン）          │
└──────────────────────┬─────────────────────────────────────────┘
                       │ HTTP（127.0.0.1 のみ。JSON + 動画の Range 配信）
┌──────────────────────┴───── backend（Python）─────────────────────┐
│ api/（FastAPI）  ──→  services（ユースケース） ──→ domain/          │
│        │ ジョブ登録                    │                            │
│        ▼                               ▼                            │
│ SQLite（メタデータ・ジョブ・編集状態）   ワークスペース（大きな生成物）│
│        ▲                                                            │
│ worker プロセス ──→ pipeline/ ──(ports)──→ adapters/                  │
│                                ffmpeg / mlx-whisper / WhisperX /     │
│                                Silero VAD / claude -p                │
└────────────────────────────────────────────────────────────────────┘
```

- `vidcut serve` が API サーバーと worker プロセスを 1 つずつ起動する。両者は SQLite のジョブ表だけで連携する（[ADR-004](./adr/ADR-004-local-app-runtime.md)）
- worker はジョブを **1 件ずつ順番に** 処理する。ML モデルのメモリ使用量と `claude -p` の利用上限を考え、並列にはしない
- `vidcut analyze <paths...>` は同じジョブ表にジョブを登録する。`--wait` を付けると、サーバーの有無に関わらず自分のプロセスで、積まれたジョブがなくなるまで処理する
- 本番では API サーバーがビルド済みの frontend も配信する。開発中は Vite の開発サーバーから API へプロキシする

## 3. コンポーネント設計

### 3-1. backend のパッケージ構成

```
backend/src/vidcut/
  domain/      純粋なデータモデルと計算（外部依存なし）
  pipeline/    処理の各段。ports.py に外部ツールと永続化（リポジトリ・ジョブ表）の抽象（Protocol）を定義する
  adapters/    ports の実装（media/: ffmpeg、sqlite/: リポジトリとジョブ表、ML、claude CLI）
  services/    ユースケース（取り込み、まとめる、編集の保存、書き出しの依頼）
  jobs/        worker のループ（ジョブ表には JobQueue の port を通して触れる）
  api/         FastAPI のルーティングと入出力スキーマ
  cli.py       コマンドライン（serve / analyze / worker / eval）
  bootstrap.py 依存の組み立て（ports に具象 adapters を注入する唯一の場所）
```

依存方向は `api / cli / jobs → services → pipeline → domain`、`adapters → pipeline.ports / domain`。
pipeline と services は adapters を import しない（テストでは偽の実装を注入する）。

### 3-2. 録画ファイルの解析パイプライン（ジョブ `analyze_recording`）

各段は入力と設定のハッシュをキーにして生成物をワークスペース（`recordings/<id>/`）に保存する。途中で失敗しても、再実行すると完了済みの段は飛ばす。
キーは「前の段のキー + 段の設定」のハッシュで、起点は録画ファイルの fingerprint。キーは `stages.json` に記録し、キーが一致して生成物が読めるときだけ段を飛ばす（壊れていれば作り直す）。

| #   | 段         | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                    | 生成物                    |
| --- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| 1   | probe      | ffprobe で長さ・解像度・フレームレート（可変か）・音声形式・録画日時を取る                                                                                                                                                                                                                                                                                                                                                                              | `probe.json`              |
| 2   | mezzanine  | 固定フレームレートの中間素材を作る（最後のフレームは音声の終わりまで延ばす）。書き出しはすべてこれを元にする。時間がかかるため**別ジョブ `make_mezzanine`（優先度低）**として登録し、解析の完了を待たせない（[ADR-002](./adr/ADR-002-vfr-mezzanine.md)）                                                                                                                                                                                                | `mezzanine.mp4`           |
| 3   | proxy      | ブラウザでのプレビュー用の軽い動画（長辺 1280px、固定フレームレート、キーフレーム間隔を短く）と、波形のピーク値                                                                                                                                                                                                                                                                                                                                         | `proxy.mp4`、`peaks.json` |
| 4   | audio      | 解析用の音声（16kHz モノラル wav）。音声の開始が映像より遅れている素材（実素材で 51ms）があるため、先頭を無音で埋めてタイムラインの 0 秒にそろえる（`aresample=first_pts=0`）                                                                                                                                                                                                                                                                           | `audio16k.wav`            |
| 5   | silence    | 音量による無音（-40dB・0.3 秒以上）を基本にし、その内側に収まる Silero VAD の発話区間（無音に紛れた小声の発話）だけを除く。VAD の区間は余韻を含み短い無音もまたぐため、無音の端にかかる区間は使わない（検証素材で、使うとチャンクが 69 → 48 につながった）。無音の間を発話チャンクにする。音声の終わりまで続く無音は、録画ファイルの終わりまで延ばす（解析用の音声は録画ファイルの長さより数十 ms 早く終わり、延ばさないと最後に断片が残る。M5 で発見） | `silence.json`            |
| 6   | transcribe | 発話チャンクごとに文字起こしする（一括で起こすと精度が落ち、幻聴が出たため）。ヒント文にフィラーを含める                                                                                                                                                                                                                                                                                                                                                | `transcript.raw.json`     |
| 7   | align      | WhisperX（日本語は wav2vec2）で文字単位のタイミングを合わせる                                                                                                                                                                                                                                                                                                                                                                                           | `transcript.json`         |
| 8   | fillers    | フィラーと要確認の印を求め、無音・フィラーの削除候補とまとめて保存する（下記）。判定と API はこれを読む                                                                                                                                                                                                                                                                                                                                                 | `analysis.json`           |

段 3〜8 を解析ジョブとして順に実行する。段 2 は別ジョブで、worker は解析と判定のジョブをすべて処理してから中間素材のジョブを処理する。書き出しジョブは中間素材の完成を待つ。worker は 1 つなので、まだできていなければ書き出しジョブの中で作る（3-4）。

**フィラーの検出（段 8）**

- 辞書（「えー」「えーと」「あのー」「うーん」「んー」等）に一致し、かつ前後に短い無音があるトークンを候補にする。
  「まあ」「その」のように内容語にもなる語は、単独のチャンクになっている場合だけ候補にする
- Whisper はフィラーを書き起こさないことがある。そのため、**VAD では発話なのに文字が 1 つも割り当たらない区間**（0.3 秒以上）を
  「未認識の発話」として要確認の印（US-04）にする。削除はしない
- 「前後に短い無音」は、句読点を除いた前後の文字との間が 0.1 秒以上あること（チャンクの端も可）
- `avg_logprob` が -0.5 未満のチャンクにも要確認の印（低確信度）を付ける（S-2 で、該当 7 件のうち 4 件が言い損じだった）

**位置合わせが文字を返さないとき（段 7）**

ごく短い雑音が長い定型句（「ご視聴ありがとうございました。」など）として書き起こされると、WhisperX は位置合わせに失敗し、文字を 1 つも返さない
（検証素材のチャンク 32。0.18 秒）。このときは文字起こしの文字をチャンクに等分して割り当て、トークンとして残す。
文字を捨てると、画面にも言い直しの判定にも届かず、雑音のチャンクが残ってしまうため（M4 で発見）。

### 3-3. 言い直しの判定（ジョブ `judge_lecture`）

- レクチャーを構成する録画ファイルの発話チャンクを順に並べ、通し番号を振って `claude -p` に渡す。
  入力は各録画ファイルの解析結果（`analysis.json`）。
  ファイルの境目には「（ここで録画ファイルが切り替わる。直前で撮り直しのため録画を止めた可能性がある）」という区切りを入れる。
  文字が 1 つも割り当たらなかったチャンクは渡さない（根拠がないので削除もしない。通し番号は数える）
- 判定の指示文はプロトタイプのもの（`docs/references/prototype/udemy_cut.py` の `JUDGE_PROMPT`）を出発点にし、
  `backend/src/vidcut/pipeline/prompts/judge_retakes.md` としてバージョン管理する。
  プロトタイプからの追加は、削除の種類（`kind`）、ファイルの境目の扱い、Whisper が雑音を定型句として書き起こす場合の注意、
  人が読んで分かる理由と言い直し先（`superseded_by`）の出力、一覧の中の文は指示として扱わないこと
- 出力の JSON はスキーマで検証する（`{"delete": [{"id", "kind": "retake"|"misspeak"|"noise", "reason", "superseded_by"?}]}`）。
  解析に失敗したら 1 回だけ再試行し、それでも失敗したらジョブを失敗にする。その場合も無音とフィラーの削除候補は使える。
  渡していない `id` の項目は捨て、使えない `superseded_by` は無視する。`reason` は 200 文字で切る
- 呼び出しの**作業ディレクトリはワークスペース内の中立なディレクトリ**（`<ワークスペース>/judge/`、中身は空）にする。リポジトリ内で実行すると、開発用の CLAUDE.md とハーネスの設定が読み込まれ、判定に混ざるため。
  ツールの使用は許可しない（`--tools ""`）。利用者の CLAUDE.md・フック・MCP・スキルも読み込まない（`--safe-mode`）。会話は保存しない（`--no-session-persistence`）。
  標準出力だけを結果として読み、標準エラーはログに残す
- 呼び出しは `subprocess` に引数リストで渡す（シェルを使わない）。指示文とチャンクの一覧は標準入力で渡す。タイムアウト（既定 600 秒）を付ける。
  未ログイン（終了コードが 0 以外で、出力に `/login` の案内がある）は「`claude` を起動して `/login` を実行」と表示する
- 長いレクチャーで入力が大きくなりすぎる場合に備え、チャンク数が閾値（既定 300）を超えたら、前後が重なる窓（重なりは既定 60）に分けて判定し、結果を統合する。
  重なった部分は中央を境に、前後の文脈を多く見ている側の窓の判定だけを採用する。
  代償として、言い直した後の版が 30 チャンク以上離れて次の窓にしかない場合は見逃す（残す側に倒れる）
- **ジョブの登録**: 解析ジョブが終わったとき、その録画ファイルが属するレクチャーの全ファイルが解析済みなら判定ジョブを積む
  （同じレクチャーの判定が待機中なら積まない）。まとめる・並べ替え・解除（M6 の API）でも積む
- **結果の保存**: 判定で作った削除候補は SQLite の `judgements` 表にレクチャーごとに 1 行で持つ（レクチャーを消すと一緒に消える）。
  削除候補の id は `<チャンクの id>-judged` で、同じチャンクを同じように判定すれば、やり直しても変わらない。
  判定の入力（指示文・チャンク・窓の設定）のハッシュも保存し、同じ入力なら `claude -p` を呼ばずに前回の結果を使う（利用上限を消費しない）
- **戻した候補の引き継ぎ**: 判定をやり直したときは、編集状態の `restored_suggestion_ids` を新しい候補へ引き継いでから（4 章）、判定結果を保存する。
  引き継げなかった id は判定結果に残し、画面の通知に使う。
  編集状態と判定結果は 1 つのトランザクションで保存する（M6）。別々に保存すると、API が間の状態
  （編集状態は新しい候補の id、判定結果は古いまま）を読んで、戻したはずの候補が削除として画面に出るため

### 3-4. 書き出し（ジョブ `export_premiere` / `export_mp4`）

1. **残す区間の計算**（domain、純粋関数）: 削除区間の集合 → 録画ファイルごとの残す区間。
   残す区間の前後に余白（前 0.15 秒・後 0.25 秒）を付けるが、隣の削除区間の発話に食い込まないよう、余白は無音区間の中に収める。
   重なった区間は統合する
2. **フレームへの丸め**: 開始は切り捨て、終了は切り上げで、中間素材のフレーム境界（既定 1/60 秒）に合わせる
3. **Premiere XML**: xmeml v4 のシーケンスを 1 つ作る。映像トラック 1 本と音声トラックに、レクチャー内の録画ファイルの
   中間素材を参照するクリップを、残す区間の順に並べる。シーケンス設定は中間素材と同じ（解像度・60fps）
4. **MP4**: 中間素材から ffmpeg の trim / atrim / concat で切り出し、`h264_videotoolbox -q:v 60` と AAC で書き出す

ワークスペースは既定で `~/VidCut/`（環境変数 `VIDCUT_WORKSPACE` で変更可）。書き出し先はワークスペースの `exports/<レクチャー名>/`。画面には保存先のパスを表示し、Finder で開くボタンを付ける。

実装の詳細（M5）:

- **入力**: 削除区間 = 無音・フィラーの候補（`analysis.json`）+ 言い直しの候補（`judgements` 表）− 戻した候補 + 手動の削除（編集状態）。
  判定がまだ（または失敗）のレクチャーは、無音とフィラーの候補だけで書き出す。
  Premiere XML と MP4 は同じ計画（`pipeline/export.py` の `ExportPlan`: 録画ファイルごとのフレーム範囲を出力の順に並べたもの）から作るので、カット点が一致する
- **中間素材の待ち方**: 書き出しジョブは中間素材のジョブより優先度が高く、先に実行されることがある。そのときは書き出しジョブの中で中間素材を作る
  （`make_mezzanine` と同じ処理・同じキャッシュ）。後から実行される `make_mezzanine` ジョブは、できた中間素材を見つけてすぐ終わる。
  すべて削除された録画ファイルの中間素材は作らない。中間素材ができていれば、元の録画ファイルがなくても書き出せる
- **Premiere XML の形**: スパイク S-1 で Premiere に読み込ませて確かめた形のまま（`backend/tests/pipeline/data/s1_synth_mezzanine.xml` と一致することをテストで固定）。
  映像 1 トラック + 音声 2 トラック（ステレオの左右）。クリップ名は元の録画ファイルの名前、参照先は `file://localhost/<中間素材の絶対パス>`（パーセントエンコード）。
  中間素材の長さ（フレーム数）は「録画ファイルの長さ × fps」の切り上げで、実際の中間素材と一致する（integration テスト）。
  シーケンスの解像度は最初のクリップの録画ファイルに合わせる。レクチャー名と録画ファイル名に含まれる、XML に書けない文字（制御文字）は `_` に置き換える
- **MP4 の切り出し**: 映像は `trim` にフレーム番号を渡す（時刻の小数だと、境界のフレームが丸めの誤差で落ちうる）。
  音声は `aresample=async=1:first_pts=0` で先頭の空白を埋めてから `atrim` で切る（埋めないと、0 秒から始まる区間の音声が前に詰まってずれる）。
  `concat` の後に `fps` フィルタで固定フレームレートの時刻に直す。音声は AAC 192kbps。つなぎ目のフェードは付けない（Premiere XML と同じ結果にする）
- **書き出し先のファイル名**: `exports/<レクチャー名>/<レクチャー名>.xml` と `.mp4`。レクチャー名はファイル名に使える形に直す
  （パスの区切り・制御文字は `_` に置き換え、先頭と末尾の `.` と空白は除き、60 文字まで）。書き出すたびに上書きする。同じ名前のレクチャーは同じ場所に書き出す。
  見えない文字（双方向制御文字など。Unicode の Cc / Cf / Zl / Zp）は除き、NFC に正規化する（3-5-2 のレクチャー名と同じ扱い）。
  `exports` または `exports/<レクチャー名>` がシンボリックリンクのときは書き出しを失敗にする（ワークスペースの外へ書かない）。
  ffmpeg の出力の一時ファイル名は呼び出しごとに一意にする（`vidcut analyze --wait` と `vidcut serve` の worker が同じ生成物を同時に作っても衝突しない）。
  強制終了されたときは一時ファイルが残る。1 日以上前のものは、次に同じ生成物を作るときに消す
- **書き出しの依頼**: `ExportService.request`（M6 の API が使う）がジョブを積む。同じ書き出しが待機中なら積まない（待機中のジョブは実行時の編集状態を読む）
- **制限**: 音声はステレオ前提。レクチャー内で解像度や音声の形式が違う録画ファイルを混ぜると、MP4 の書き出しは失敗する（`concat` が受け付けない）。
  Premiere XML は書き出せるが、シーケンスの解像度は最初のクリップのものになり、違う解像度のクリップの拡大・縮小は Premiere 側で行う。
  残す区間が 1 つもないレクチャーの書き出しは失敗にする
- **フレームレート**: 書き出しと中間素材のフレームレートは同じ設定（`ExportSettings.fps`。既定 60）から決める（`bootstrap.py`）

### 3-5. API（FastAPI）

待ち受けは `127.0.0.1:8765`（開発中は Vite の開発サーバーが `/api` をここへ転送する）。レスポンスはすべて `{success, data, error}` の形にそろえる（`.claude/rules/common/patterns.md`）。
frontend の型は OpenAPI スキーマから `openapi-typescript` で生成する。

| メソッド | パス                                      | 用途                                                                                                                               |
| -------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| GET      | `/api/fs?path=`                           | 投入するファイル・フォルダを選ぶための一覧。ホームディレクトリ配下のみ、動画ファイルとフォルダだけを返す                           |
| POST     | `/api/imports`                            | ファイルとフォルダのパス一覧を受け取り、録画ファイルを登録する。1 ファイル = 1 レクチャーとして作り、解析ジョブを登録する（US-10） |
| GET      | `/api/lectures`                           | レクチャー一覧（構成ファイル、解析と判定の状態）                                                                                   |
| GET      | `/api/lectures/{id}`                      | 編集画面に必要なもの一式（文字起こし、削除区間、編集状態、要確認の印）                                                             |
| POST     | `/api/lectures/merge`                     | 複数のレクチャーを 1 つにまとめる（順序付き）。判定ジョブを登録する（US-11）                                                       |
| PUT      | `/api/lectures/{id}/order`                | 構成ファイルの順序を変える。判定ジョブを登録する（待機中なら積まない）                                                             |
| POST     | `/api/lectures/{id}/split`                | まとめたレクチャーを録画ファイルごとに戻す                                                                                         |
| PUT      | `/api/lectures/{id}/edits`                | 編集状態を保存する（`version` による楽観的排他）                                                                                   |
| POST     | `/api/lectures/{id}/exports`              | 書き出しジョブを登録する（`format`: `premiere_xml` / `mp4`）                                                                       |
| POST     | `/api/lectures/{id}/reanalyze`            | レクチャーの録画ファイルを解析し直す（解析ロジックを更新したあとに使う）。終わると判定も積まれる                                   |
| GET      | `/api/jobs` / POST `/api/jobs/{id}/retry` | 進捗一覧と、失敗したジョブの再実行                                                                                                 |
| GET      | `/api/recordings/{id}/proxy`、`/peaks`    | プレビュー用の動画（Range 対応）と波形のピーク値                                                                                   |

応答と入力の決まり（M6）:

- **状態コード**: 見つからないものは 404、入力の誤りは 422、編集状態の版の食い違いは 409、想定していない失敗は 500。
  どれも `{success: false, data: null, error: "..."}` で返す。`error` は定型文か、入力の誤りを説明する文だけで、例外の文やスタックトレースは入れない（ログに出す）
- **入力の上限**（pydantic の厳格な型。`"1"` や `1.0` を整数として受け付けず、知らない項目は拒む）: id は英数字と `_` `-` の 64 文字まで、
  パスは 4,096 文字・1 回の取り込みは 200 件まで、まとめるレクチャーは 50 件まで、題名は 100 文字まで（超えたら拒む）、
  手動の削除は 2,000 件・戻した候補は 20,000 件（id は 100 文字）まで、時刻は 0〜24 時間
- **出力は許可リスト方式**: domain のオブジェクトをそのまま返さず、スキーマ（`api/inputs.py`・`api/outputs.py`）に項目を 1 つずつ写す。
  ジョブは種別（`error_code`）と定型文（`error_message`）だけを返す
- **`/api/fs` と `/api/imports`**: パスは絶対パスだけを受け付ける。ホームの外・隠しフォルダ・動画以外のファイル・ファイルシステムが扱えないパス（NUL 文字、長すぎる名前、循環するリンク）が 1 つでもあれば、取り込みは何もせず 422。
  見つからないパスは `failed` に入れて、ほかの取り込みを続ける。フォルダは、直下の動画ファイル（隠しファイルと、外を指すリンクを除く）に展開する。
  1 つのフォルダの一覧は 1,000 件まで（超えた分は省き、`truncated` で知らせる。取り込みのときの展開は打ち切らない）
- **OpenAPI**: 失敗の応答（401・403・404・422・500、編集の保存は 409 も）は `ErrorOut`（`{success: false, data: null, error}`）として載せる。FastAPI 既定の `HTTPValidationError` は使わない。proxy は `video/mp4`（200 と 206）
- **保存先の表示**（3-4）: 書き出し先のパスを返す項目はまだない。M7 で書き出しボタンを作るときに足す

ブラウザのファイル選択ではファイルの絶対パスが取れず、数 GB の素材をアップロードしてコピーするのは無駄が大きい。
そのため、サーバー側でフォルダを辿る簡易ブラウザ（`/api/fs`）で選ぶ方式にする（[ADR-004](./adr/ADR-004-local-app-runtime.md)）。

### 3-5-1. ローカル API の防御

127.0.0.1 で待ち受けるだけでは、ブラウザで開いた悪意あるページからの CSRF や DNS rebinding を防げない（2026-10-03 のセキュリティレビューの指摘）。
特に `/api/fs` はホーム配下を列挙できるため、次をすべて実装する。

- **Host の検証**: `Host` ヘッダーが `127.0.0.1:8765` / `localhost:8765` 以外なら拒否する（DNS rebinding 対策）
- **Origin の検証**: `Origin` があり、自分自身（と開発中の Vite のオリジン）以外なら拒否する。CORS は許可しない
- **起動ごとのトークン**: `vidcut serve` が起動のたびにランダムなトークンを作り、配信する HTML に埋め込む。すべての `/api` で `X-VidCut-Token` ヘッダーを必須にする。
  例外は `/api/recordings/{id}/proxy` だけで、`<video>` はヘッダーを付けられないため、同じトークンを `?token=` のクエリで受け取る（ユーザー決定、2026-10-03）。
  トークンが端末のログに残らないよう、アクセスログにはクエリを出さない
- **Content-Type**: 状態を変える要求は `application/json` だけを受け付ける
- **パスの正規化**: `/api/fs` と `/api/imports` のパスは `Path.resolve(strict=True)` で実体を解決してから `is_relative_to(Path.home())` で判定する（`..` とシンボリックリンク対策）。
  隠しファイル・隠しフォルダ（`~/.ssh` など）は返さず、受け付けない
- **外部コマンドへの入力**: ffmpeg には解決済みの絶対パスだけを渡す（`-` で始まる値をオプションと誤解させない）。
  `claude -p` の出力に含まれる `id` は、渡したチャンクの範囲内のものだけを受け付ける（文字起こしの内容によるプロンプトインジェクション対策）

実装（M6。`api/security.py` の ASGI ミドルウェアが、アプリに渡す前にすべての要求を確かめる）:

- Host と Origin は `/api` 以外（配信する HTML）にも適用する。HTML にはトークンを埋め込むため
- 断るときの応答: Host・Origin は 403、トークンは 401、本文が JSON 以外は 415、本文が上限（1MB）を超えると 413、
  長さの分からない本文（chunked）は 411。トークンの比較は一定時間で行う
- 本文のない POST（解除・再解析・再実行）は Content-Type を問わない。トークンのヘッダーは別のページからは付けられない（CORS を許可していない）
- 対話式のドキュメント（`/docs`・`/redoc`・`/openapi.json`）は配信しない（画面の JS を外部の CDN から読むため）。スキーマは `app.openapi()` で取り出す

### 3-5-2. API を支える決定（M6）

- **SQLite の接続**: API サーバーはリクエストごとに接続を開いて閉じる（`bootstrap.build_api` の `Api.services()`。worker と CLI は `build_app` が接続を 1 本持つ）。FastAPI は同期の処理をスレッドプールで動かし、
  依存の準備と本体が別のスレッドになることがあるので、接続は `check_same_thread=False` で開き、1 つのリクエストの中で直列に使う
  （リクエストをまたいで共有しない）。スキーマの移行は起動時に 1 回だけ行う。WAL なので、読み取りは worker の書き込みを待たない
- **まとめて確定する保存**: 複数のリポジトリにまたがる保存（判定結果と編集状態、まとめる・解除とその編集状態・ジョブ）は、
  services が `Atomic`（ports）で囲んで 1 つのトランザクションにする。途中で例外が出たら、囲んだ保存をすべて取り消す
- **エラーの分類**: ジョブの失敗は、worker が例外の型から種別（`error_code`）に分けて jobs 表に記録する。
  API は種別と、種別ごとの定型文だけを返す。生のエラー文（絶対パスや ffmpeg / `claude` の出力を含む）は jobs 表とログに残し、API では返さない
  （一覧と詳細が返すジョブの型 `JobView` は、生のエラー文を持たない）。
  取り込みの失敗（`/api/imports`）も同じ種別で返す

  | 種別                | 例外                    | 意味                                               |
  | ------------------- | ----------------------- | -------------------------------------------------- |
  | `login_required`    | `LoginRequiredError`    | `claude` にログインしていない                      |
  | `tool_failed`       | `ExternalToolError`     | ffmpeg / `claude` が失敗した・時間切れ・未導入     |
  | `unsupported_media` | `UnsupportedMediaError` | 処理できない形式の録画ファイル                     |
  | `source_missing`    | `FileNotFoundError`     | 元の録画ファイルが見つからない                     |
  | `not_found`         | `NotFoundError`         | レクチャーや録画ファイルがない・解析が済んでいない |
  | `conflict`          | `VersionConflictError`  | 編集状態が更新され続けて反映できなかった           |
  | `invalid_output`    | `JudgeOutputError`      | 判定の出力を読み取れなかった                       |
  | `nothing_to_export` | `NothingToExportError`  | 残す区間が 1 つもない                              |
  | `internal`          | 上記以外                | 想定していない失敗（詳細はログ）                   |

- **再解析**: `reanalyze` は、レクチャーの各録画ファイルの解析ジョブを積む（同じ録画ファイルの解析が待機中なら積まない）。
  段のキャッシュ（3-2）があるので、キーが変わった段からだけ作り直す。解析が終わると、取り込みのときと同じ仕組みで判定が積まれる
- **レクチャー名**: 人の入力（まとめるときの題名）とファイル名（取り込み）から来る。保存する前に NFC に正規化し、
  改行とタブは空白 1 つに置き換え、そのほかの見えない文字（Unicode の Cc / Cf / Zl / Zp）を除き、前後の空白を落とし、100 文字までにする。空になった入力は受け付けない
  （ファイル名から作るときは `untitled`）
- **まとめる・並べ替え・解除と編集状態**: 編集状態（手動の削除・戻した候補）は、録画ファイル単位で新しいレクチャーへ引き継ぐ。
  まとめるときは元のレクチャーの編集状態を合わせ、解除するときは録画ファイルごとに分ける
  （戻した候補は、解析結果と判定結果からどの録画ファイルのものかを求める。分からないものは捨てる）。
  元のレクチャーに対する待機中のジョブ（判定・書き出し）は消す。処理中のジョブは消さず、レクチャーがなくなったことで失敗（`not_found`）として残る。
  レクチャーの置き換え・編集状態・ジョブは 1 つのトランザクションで保存し、そのあと判定ジョブを積む。
  並べ替えではレクチャーの id が変わらないので、編集状態もジョブもそのまま残る。順序が同じなら何もしない
- **言語モデルと外部ツール由来の文字列**: 判定の `reason` は言語モデルの自由記述。API は文字列をそのまま JSON で返し（HTML エスケープはしない。二重のエスケープを避ける）、
  長さだけを制限する。画面は React の通常の描画（自動でエスケープされる）で表示し、`dangerouslySetInnerHTML` は使わない
- **書き出し先の前提**: シンボリックリンクの確認と書き込みの間に、同じ利用者の別のプロセスが差し替える余地は残る（利用者 1 名のローカルアプリなので受け入れる）。
  見た目が紛らわしいだけの文字（全角のピリオドなど）は、パスの区切りとして働かないので残す

### 3-6. frontend

| 画面     | 構成                                                                                                                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 素材一覧 | レクチャーの一覧（状態: 待機中・解析中・判定中・編集待ち・失敗）。「投入」ダイアログ（`/api/fs` のフォルダブラウザ）。複数選択して「まとめる」、まとめたレクチャー内の並べ替え・解除。失敗の再実行 |
| 編集画面 | 左: プレビュー、右: 文字起こし、下: 波形タイムライン。上部に書き出しボタン                                                                                                                         |

- **文字起こし**: トークン（文字または語）を `span` で並べた読み取り専用のテキストとして描く。選択範囲は DOM の Selection API でトークンの範囲に変換し、
  Delete / Backspace で手動の削除区間を作る。削除済みのトークンは取り消し線と背景色（種類ごとの色）で表し、クリックで復活できる。
  文字起こしの文字を書き換える機能は MVP には含めない（テロップ対応のときに追加する）
- **要確認の印**: 確信度が閾値未満のトークンと「未認識の発話」に下線を引き、次の要確認箇所へ移動するキー操作を付ける
- **判定理由**: 言い直しの削除区間にカーソルを合わせると理由と「どこで言い直したか」を表示し、そこへ移動できる
- **波形**: wavesurfer.js（v7）に backend で計算したピーク値を渡して描く（巨大な音声をブラウザでデコードしない）。削除区間は regions プラグインで色分けする
- **カット後のプレビュー**: 録画ファイルごとの proxy 動画を切り替えながら、削除区間に入ったら次の残す区間へシークする。
  判定には `requestVideoFrameCallback` を使う（`timeupdate` は間隔が粗く、削除区間の頭が聞こえてしまうため）
- **状態と取り消し**: 編集状態は不変のオブジェクトとして扱い、`useReducer` と履歴スタックで undo / redo を実現する。
  変更は 1 秒の遅延をおいて自動保存する（US-08）

## 4. データモデル

時刻はすべて**録画ファイル内の時刻を整数ミリ秒**で持つ（浮動小数の誤差の蓄積を避ける）。
出力（カット後）の時刻は保存せず、削除区間から計算して求める。これにより、将来のテロップ・SRT（US-13）は
「残ったトークン」と「録画ファイル内の時刻 → 出力の時刻」の変換関数だけで作れる。

```python
# domain（frozen dataclass。変更はすべて新しいオブジェクトを返す）

Interval:       start_ms, end_ms                               # 半開区間 [start, end)。以下の span はすべてこれ

Recording:      id, source_path, fingerprint(サイズ + 更新日時 + 先頭と末尾のハッシュ),
                duration_ms, recorded_at, media: MediaInfo(width, height, is_vfr, avg_fps, audio_rate)
SpeechChunk:    id, recording_id, span            # 無音で区切った発話のまとまり
Token:          id, recording_id, chunk_id, text, span,
                asr_confidence(0..1), align_score(0..1)        # 日本語では 1 文字 = 1 トークンが基本
                # asr_confidence はチャンクの avg_logprob から min(1, exp(avg_logprob))。同じチャンクの文字は同じ値
Silence:        recording_id, span
Lecture:        id, title, recording_ids: tuple[str, ...]      # 順序付き。1 本以上
CutSuggestion:  id, recording_id, span,
                kind: silence | filler | retake | misspeak | noise,
                reason（言い直し系は必須）, superseded_by(言い直し後の位置、任意)
ManualCut:      id, recording_id, span                         # 人が追加した削除区間
EditState:      lecture_id, version,
                restored_suggestion_ids: frozenset[str],       # 自動の削除候補を戻したもの
                manual_cuts: tuple[ManualCut, ...]             # 人が追加した削除区間（ミリ秒。画面がトークンの選択範囲から求める）
ReviewMark:     recording_id, span, kind: low_confidence | unrecognized_speech
Judgement:      lecture_id, input_key(判定の入力のハッシュ),
                suggestions: tuple[CutSuggestion, ...],        # retake / misspeak / noise
                dropped_restored_ids: tuple[str, ...]          # やり直しで引き継げなかった「戻した候補」
Job:            id, kind, target_id, status: queued | running | succeeded | failed,
                stage, progress(0..1), error,           # 作成・更新日時は永続化層が持つ
                error_code                              # 失敗の種別（3-5-2）。API はこれだけを返し、error（生の文）は返さない
                # 優先度は種類で決まる（JobKind.priority。中間素材が最も低い）。同じ優先度は登録順
```

- 実際に削除される区間 = （自動の削除候補 − 戻したもの）∪ 人が追加した削除区間
- 判定をやり直すと `retake` / `misspeak` / `noise` の候補は作り直される。戻した候補（`restored_suggestion_ids`）は、
  同じ録画ファイルで開始・終了の差が 200ms 以内の言い直し系の新しい候補へ引き継ぎ、引き継げなかったものは破棄して画面で通知する
- 保存先は SQLite（メタデータ・ジョブ・編集状態）とワークスペースのファイル（文字起こし・波形などの大きなもの）

## 5. トレードオフ

| 選択             | 採用                           | 理由・代償                                                                                                    |
| ---------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 書き出しの元素材 | 固定フレームレートの中間素材   | 音ズレを確実に避けられる。代わりにディスク容量と解析時間が増える（[ADR-002](./adr/ADR-002-vfr-mezzanine.md)） |
| 文字起こしの単位 | 無音で区切ったチャンクごと     | プロトタイプで一括より精度が高かった。代わりに文脈が途切れ、チャンクの頭の認識が落ちることがある              |
| フィラーの検出   | 辞書 + 無音の位置（規則）      | 速く、説明できる。Whisper が書き起こさないフィラーは「未認識の発話」として人に回す                            |
| 言い直しの判定   | `claude -p`（レクチャー単位）  | ファイルをまたいだ判断ができ、費用がかからない。代わりに出力は確定的でなく、利用上限の影響を受ける            |
| ジョブの実行     | worker プロセス 1 つで直列     | 単純でメモリ使用量が読める。代わりに大量に投入すると待ち時間が長い                                            |
| テキスト編集     | 自前の読み取り専用トークン表示 | 必要なのは選択と削除だけなので、エディタフレームワークは過剰。文字の修正は将来                                |
| 永続化           | SQLite + ファイル              | 標準ライブラリだけで済み、ジョブ表の排他も扱える                                                              |

## 6. テスト戦略

| 種類        | 対象                                                                                              | 方法                                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| unit        | domain（残す区間・余白・フレームへの丸め・時刻の変換・候補の引き継ぎ）、pipeline の各段、services | 偽の ports を注入。外部ツールは呼ばない                                                                                                              |
| integration | adapters（ffmpeg、SQLite、XML の生成）                                                            | ffmpeg の `lavfi` で生成した数秒の小さな素材（可変フレームレートを含む）を使う。ML と `claude -p` の adapter は `@pytest.mark.ml` で既定では除外する |

可変フレームレートの回帰テスト（S-1 の人工素材と同じ作り）: 中間素材の映像の長さが音声と一致すること、切り出した MP4 で白枠とビープの時刻差が 1 フレーム以内であることを integration テストで自動検証する。
| E2E | 投入 → 解析 → 編集 → 書き出し | Playwright。環境変数で ML と判定を偽の実装に差し替え、結果を決定的にする |
| 精度評価 | 言い直しの判定 | `vidcut eval judge --chunks sample-chunks.json --truth sample-judge-ground-truth.json` で判定し、正解データと比べて適合率・再現率を出す（PRD 3-1）。`--lecture <題名または id>` を使うと、解析済みのレクチャー（実際のパイプラインの文字起こし）で測る。`claude` を呼ぶので通常のテストには含めない |

## 7. 未解決の問い

| #   | 問い                                                                                                                                     | 影響範囲 | 優先度 |

### 実装前のスパイク（検証）

実装計画の最初に、以下を検証素材（`~/Desktop/s05-12sample.mov`）で確かめ、ADR-002・ADR-003 を確定させる。

1. **S-1 Premiere XML**: 中間素材を参照した XML と、元素材を参照した XML を Premiere で読み込み、音ズレとフレーム欠けを比べる（D-3）
   - **結果（2026-10-03）**: 元素材の参照は使えない（Premiere がフレームを均等に並べ直し、大きくずれる）。中間素材の参照は期待どおり。詳細は ADR-002
2. **S-2 文字起こし**: mlx-whisper（large-v3-turbo）と whisper.cpp（large-v3）で、精度・フィラーの残り方・処理時間を比べる（D-4）
   - **結果（2026-10-03）**: mlx-whisper large-v3-turbo を採用（精度が高く、99 秒）。詳細は ADR-003
3. **S-3 位置合わせ**: WhisperX の日本語の位置合わせが Python 3.12 + Apple Silicon で動き、文字単位の時刻が実用的な精度で出るか
   - **結果（2026-10-03）**: 動作した。全文字に時刻が付き、21 秒。詳細は ADR-003
4. **S-4 判定の基準値**: プロトタイプの指示文で `sample-chunks.json` を判定し、正解データに対する適合率・再現率の現状値を測る
   - **結果（2026-10-03 実施）**: 3 回実行し、3 回とも 21 件を削除して正解と完全一致（適合率・再現率とも 100%）。
     ただし、指示文はこの素材で調整されたものなので、過学習の可能性が高い。汎化性能は、実際の素材 3 本の人によるチェック（PRD 3-2）で確かめる。
     正解データを増やす（別の素材で人が判定する）と、暫定指標の信頼性が上がる
   - **M4 での再計測（2026-10-03）**: 製品の指示文（`judge_retakes.md`）と `vidcut eval judge` で、プロトタイプのチャンク（1 回）と
     実際のパイプラインの解析結果（mlx-whisper。3 回）のどちらも 21 件を削除して正解と完全一致。チャンク 32 の幻聴も `noise` として削除された。
