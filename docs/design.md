# Design Doc: vid-cut MVP

**ステータス:** 承認済み
**作成日:** 2026-10-03
**関連 PRD:** [docs/prd.md](./prd.md)
**関連 ADR:** [ADR-001](./adr/ADR-001-language-and-stack.md)（言語）、[ADR-002](./adr/ADR-002-vfr-mezzanine.md)（可変フレームレート）、
[ADR-003](./adr/ADR-003-transcription-engine.md)（文字起こし）、[ADR-004](./adr/ADR-004-local-app-runtime.md)（実行形態と永続化）

## 1. 概要

録画ファイルを解析して削除候補を作り、レクチャー単位の編集画面で人が確認・修正し、Premiere XML と MP4 を書き出す。
すべてローカルの 1 台の Mac（Apple Silicon）で動き、利用者は制作者本人 1 名。

処理は 3 つの単位に分かれる。

| 単位         | 処理                                                                      | 再実行の条件                                     |
| ------------ | ------------------------------------------------------------------------- | ------------------------------------------------ |
| 録画ファイル | 検査 → 中間素材の作成 → 無音検出 → 文字起こし → 位置合わせ → フィラー検出 | 元ファイルが変わったとき（通常は 1 回だけ）      |
| レクチャー   | 言い直しの判定（ファイルをまたぐ）                                        | 構成（ファイルの組み合わせ・順序）が変わったとき |
| 書き出し     | 残す区間の計算 → Premiere XML / MP4                                       | 書き出しのたび                                   |

録画ファイル単位の重い処理（ML）と、レクチャー単位の軽い処理（判定）を分けることで、
レクチャーのまとめ方を変えても文字起こしをやり直さずに済む（US-11）。

## 2. アーキテクチャ

```
┌────────────── ブラウザ（frontend: React + Vite） ───────────────┐
│ 素材一覧（投入・進捗・まとめる）     編集画面（3 ペイン）          │
└──────────────────────┬─────────────────────────────────────────┘
                       │ HTTP（127.0.0.1 のみ。JSON + 動画の Range 配信）
┌──────────────────────┴───── backend（Python）─────────────────────┐
│ api/（FastAPI）  ──→  services（ユースケース） ──→ domain/          │
│        │ ジョブ登録                    │                            │
│        ▼                               ▼                            │
│ SQLite（メタデータ・ジョブ・編集状態）   ワークスペース（大きな生成物）│
│        ▲                                                            │
│ worker プロセス ──→ pipeline/ ──(ports)──→ adapters/                  │
│                                ffmpeg / mlx-whisper / WhisperX /     │
│                                Silero VAD / claude -p                │
└────────────────────────────────────────────────────────────────────┘
```

- `vidcut serve` が API サーバーと worker プロセスを 1 つずつ起動する。両者は SQLite のジョブ表だけで連携する（[ADR-004](./adr/ADR-004-local-app-runtime.md)）
- worker はジョブを **1 件ずつ順番に** 処理する。ML モデルのメモリ使用量と `claude -p` の利用上限を考え、並列にはしない
- `vidcut analyze <paths...>` は同じジョブ表にジョブを登録する。サーバーが起動していなければ `--wait` で自分で処理する
- 本番では API サーバーがビルド済みの frontend も配信する。開発中は Vite の開発サーバーから API へプロキシする

## 3. コンポーネント設計

### 3-1. backend のパッケージ構成

```
backend/src/vidcut/
  domain/      純粋なデータモデルと計算（外部依存なし）
  pipeline/    処理の各段。ports.py に外部ツールの抽象（Protocol）を定義する
  adapters/    ports の実装（ffmpeg、ML、claude CLI）と SQLite リポジトリ
  services/    ユースケース（取り込み、まとめる、編集の保存、書き出しの依頼）
  jobs/        ジョブ表の操作と worker のループ
  api/         FastAPI のルーティングと入出力スキーマ
  cli.py       コマンドライン（serve / analyze / worker / eval）
  bootstrap.py 依存の組み立て（ports に具象 adapters を注入する唯一の場所）
```

依存方向は `api / cli / jobs → services → pipeline → domain`、`adapters → pipeline.ports / domain`。
pipeline と services は adapters を import しない（テストでは偽の実装を注入する）。

### 3-2. 録画ファイルの解析パイプライン（ジョブ `analyze_recording`）

各段は入力と設定のハッシュをキーにして生成物をワークスペースに保存する。途中で失敗しても、再実行すると完了済みの段は飛ばす。

| #   | 段         | 内容                                                                                                                          | 生成物                    |
| --- | ---------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| 1   | probe      | ffprobe で長さ・解像度・フレームレート（可変か）・音声形式・録画日時を取る                                                    | `probe.json`              |
| 2   | mezzanine  | 固定フレームレート（既定 60fps）の中間素材を作る。書き出しはすべてこれを元にする（[ADR-002](./adr/ADR-002-vfr-mezzanine.md)） | `mezzanine.mp4`           |
| 3   | proxy      | ブラウザでのプレビュー用の軽い動画（長辺 1280px、固定フレームレート、キーフレーム間隔を短く）と、波形のピーク値               | `proxy.mp4`、`peaks.json` |
| 4   | audio      | 解析用の音声（16kHz モノラル wav）                                                                                            | `audio16k.wav`            |
| 5   | silence    | Silero VAD の発話区間と、音量による無音検出（-40dB・0.3 秒以上）を併用して、無音区間と発話チャンクを決める                    | `silence.json`            |
| 6   | transcribe | 発話チャンクごとに文字起こしする（一括で起こすと精度が落ち、幻聴が出たため）。ヒント文にフィラーを含める                      | `transcript.raw.json`     |
| 7   | align      | WhisperX（日本語は wav2vec2）で文字単位のタイミングを合わせる                                                                 | `transcript.json`         |
| 8   | fillers    | フィラーを検出する（下記）                                                                                                    | `fillers.json`            |

段 2〜4 は互いに独立しているが、worker は 1 件ずつ処理するので順番に実行する。

**フィラーの検出（段 8）**

- 辞書（「えー」「えーと」「あのー」「うーん」「んー」等）に一致し、かつ前後に短い無音があるトークンを候補にする。
  「まあ」「その」のように内容語にもなる語は、単独のチャンクになっている場合だけ候補にする
- Whisper はフィラーを書き起こさないことがある。そのため、**VAD では発話なのに文字が 1 つも割り当たらない区間**を
  「未認識の発話」として要確認の印（US-04）にする。削除はしない

### 3-3. 言い直しの判定（ジョブ `judge_lecture`）

- レクチャーを構成する録画ファイルの発話チャンクを順に並べ、通し番号を振って `claude -p` に渡す。
  ファイルの境目には「（ここで録画ファイルが切り替わる。直前で撮り直しのため録画を止めた可能性がある）」という区切りを入れる
- 判定の指示文はプロトタイプのもの（`docs/references/prototype/udemy_cut.py` の `JUDGE_PROMPT`）を出発点にし、
  `backend/src/vidcut/pipeline/prompts/judge_retakes.md` としてバージョン管理する
- 出力の JSON はスキーマで検証する（`{"delete": [{"id", "kind": "retake"|"misspeak"|"noise", "reason", "superseded_by"?}]}`）。
  解析に失敗したら 1 回だけ再試行し、それでも失敗したらジョブを失敗にする。その場合も無音とフィラーの削除候補は使える
- 呼び出しの**作業ディレクトリはワークスペース内の中立なディレクトリ**にする。リポジトリ内で実行すると、開発用の CLAUDE.md とハーネスの設定が読み込まれ、判定に混ざるため。ツールの使用は許可しない。標準出力だけを結果として読み、標準エラーはログに残す
- 呼び出しは `subprocess` に引数リストで渡す（シェルを使わない）。タイムアウトを付ける。未ログインのエラーは「`claude` で `/login` が必要」と表示する
- 長いレクチャーで入力が大きくなりすぎる場合に備え、チャンク数が閾値（既定 300）を超えたら、前後が重なる窓に分けて判定し、結果を統合する

### 3-4. 書き出し（ジョブ `export_premiere` / `export_mp4`）

1. **残す区間の計算**（domain、純粋関数）: 削除区間の集合 → 録画ファイルごとの残す区間。
   残す区間の前後に余白（前 0.15 秒・後 0.25 秒）を付けるが、隣の削除区間の発話に食い込まないよう、余白は無音区間の中に収める。
   重なった区間は統合する
2. **フレームへの丸め**: 開始は切り捨て、終了は切り上げで、中間素材のフレーム境界（既定 1/60 秒）に合わせる
3. **Premiere XML**: xmeml v4 のシーケンスを 1 つ作る。映像トラック 1 本と音声トラックに、レクチャー内の録画ファイルの
   中間素材を参照するクリップを、残す区間の順に並べる。シーケンス設定は中間素材と同じ（解像度・60fps）
4. **MP4**: 中間素材から ffmpeg の trim / atrim / concat で切り出し、`h264_videotoolbox -q:v 60` と AAC で書き出す

ワークスペースは既定で `~/VidCut/`（環境変数 `VIDCUT_WORKSPACE` で変更可）。書き出し先はワークスペースの `exports/<レクチャー名>/`。画面には保存先のパスを表示し、Finder で開くボタンを付ける。

### 3-5. API（FastAPI）

レスポンスはすべて `{success, data, error}` の形にそろえる（`.claude/rules/common/patterns.md`）。
frontend の型は OpenAPI スキーマから `openapi-typescript` で生成する。

| メソッド | パス                                      | 用途                                                                                                                               |
| -------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| GET      | `/api/fs?path=`                           | 投入するファイル・フォルダを選ぶための一覧。ホームディレクトリ配下のみ、動画ファイルとフォルダだけを返す                           |
| POST     | `/api/imports`                            | ファイルとフォルダのパス一覧を受け取り、録画ファイルを登録する。1 ファイル = 1 レクチャーとして作り、解析ジョブを登録する（US-10） |
| GET      | `/api/lectures`                           | レクチャー一覧（構成ファイル、解析と判定の状態）                                                                                   |
| GET      | `/api/lectures/{id}`                      | 編集画面に必要なもの一式（文字起こし、削除区間、編集状態、要確認の印）                                                             |
| POST     | `/api/lectures/merge`                     | 複数のレクチャーを 1 つにまとめる（順序付き）。判定ジョブを登録する（US-11）                                                       |
| PUT      | `/api/lectures/{id}/order`                | 構成ファイルの順序を変える。判定ジョブを登録し直す                                                                                 |
| POST     | `/api/lectures/{id}/split`                | まとめたレクチャーを録画ファイルごとに戻す                                                                                         |
| PUT      | `/api/lectures/{id}/edits`                | 編集状態を保存する（`version` による楽観的排他）                                                                                   |
| POST     | `/api/lectures/{id}/exports`              | 書き出しジョブを登録する（`format`: `premiere_xml` / `mp4`）                                                                       |
| GET      | `/api/jobs` / POST `/api/jobs/{id}/retry` | 進捗一覧と、失敗したジョブの再実行                                                                                                 |
| GET      | `/api/recordings/{id}/proxy`、`/peaks`    | プレビュー用の動画（Range 対応）と波形のピーク値                                                                                   |

ブラウザのファイル選択ではファイルの絶対パスが取れず、数 GB の素材をアップロードしてコピーするのは無駄が大きい。
そのため、サーバー側でフォルダを辿る簡易ブラウザ（`/api/fs`）で選ぶ方式にする（[ADR-004](./adr/ADR-004-local-app-runtime.md)）。

### 3-6. frontend

| 画面     | 構成                                                                                                                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 素材一覧 | レクチャーの一覧（状態: 待機中・解析中・判定中・編集待ち・失敗）。「投入」ダイアログ（`/api/fs` のフォルダブラウザ）。複数選択して「まとめる」、まとめたレクチャー内の並べ替え・解除。失敗の再実行 |
| 編集画面 | 左: プレビュー、右: 文字起こし、下: 波形タイムライン。上部に書き出しボタン                                                                                                                         |

- **文字起こし**: トークン（文字または語）を `span` で並べた読み取り専用のテキストとして描く。選択範囲は DOM の Selection API でトークンの範囲に変換し、
  Delete / Backspace で手動の削除区間を作る。削除済みのトークンは取り消し線と背景色（種類ごとの色）で表し、クリックで復活できる。
  文字起こしの文字を書き換える機能は MVP には含めない（テロップ対応のときに追加する）
- **要確認の印**: 確信度が閾値未満のトークンと「未認識の発話」に下線を引き、次の要確認箇所へ移動するキー操作を付ける
- **判定理由**: 言い直しの削除区間にカーソルを合わせると理由と「どこで言い直したか」を表示し、そこへ移動できる
- **波形**: wavesurfer.js（v7）に backend で計算したピーク値を渡して描く（巨大な音声をブラウザでデコードしない）。削除区間は regions プラグインで色分けする
- **カット後のプレビュー**: 録画ファイルごとの proxy 動画を切り替えながら、削除区間に入ったら次の残す区間へシークする。
  判定には `requestVideoFrameCallback` を使う（`timeupdate` は間隔が粗く、削除区間の頭が聞こえてしまうため）
- **状態と取り消し**: 編集状態は不変のオブジェクトとして扱い、`useReducer` と履歴スタックで undo / redo を実現する。
  変更は 1 秒の遅延をおいて自動保存する（US-08）

## 4. データモデル

時刻はすべて**録画ファイル内の時刻を整数ミリ秒**で持つ（浮動小数の誤差の蓄積を避ける）。
出力（カット後）の時刻は保存せず、削除区間から計算して求める。これにより、将来のテロップ・SRT（US-13）は
「残ったトークン」と「録画ファイル内の時刻 → 出力の時刻」の変換関数だけで作れる。

```python
# domain（frozen dataclass。変更はすべて新しいオブジェクトを返す）

Recording:      id, source_path, fingerprint(サイズ + 更新日時 + 先頭と末尾のハッシュ),
                duration_ms, recorded_at, media: MediaInfo(width, height, is_vfr, avg_fps, audio_rate)
SpeechChunk:    id, recording_id, start_ms, end_ms            # 無音で区切った発話のまとまり
Token:          id, recording_id, chunk_id, text, start_ms, end_ms,
                asr_confidence(0..1), align_score(0..1)        # 日本語では 1 文字 = 1 トークンが基本
Silence:        recording_id, start_ms, end_ms
Lecture:        id, title, recording_ids: tuple[str, ...]      # 順序付き。1 本以上
CutSuggestion:  id, recording_id, start_ms, end_ms,
                kind: silence | filler | retake | misspeak | noise,
                reason, superseded_by(言い直し後の位置、任意), origin: auto
EditState:      lecture_id, version,
                overrides: {suggestion_id: "restored"},        # 自動の削除候補を戻したもの
                manual_cuts: tuple[ManualCut, ...]             # 人が追加した削除区間（トークン範囲）
ReviewMark:     recording_id, start_ms, end_ms, kind: low_confidence | unrecognized_speech
Job:            id, kind, target_id, status: queued | running | succeeded | failed,
                stage, progress(0..1), error, created_at, updated_at
```

- 実際に削除される区間 = （自動の削除候補 − 戻したもの）∪ 人が追加した削除区間
- 判定をやり直すと `retake` / `misspeak` / `noise` の候補は作り直される。その候補に対する `overrides` は、
  時刻範囲がほぼ一致する新しい候補へ引き継ぎ、引き継げなかったものは破棄して画面で通知する
- 保存先は SQLite（メタデータ・ジョブ・編集状態）とワークスペースのファイル（文字起こし・波形などの大きなもの）

## 5. トレードオフ

| 選択             | 採用                           | 理由・代償                                                                                                    |
| ---------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 書き出しの元素材 | 固定フレームレートの中間素材   | 音ズレを確実に避けられる。代わりにディスク容量と解析時間が増える（[ADR-002](./adr/ADR-002-vfr-mezzanine.md)） |
| 文字起こしの単位 | 無音で区切ったチャンクごと     | プロトタイプで一括より精度が高かった。代わりに文脈が途切れ、チャンクの頭の認識が落ちることがある              |
| フィラーの検出   | 辞書 + 無音の位置（規則）      | 速く、説明できる。Whisper が書き起こさないフィラーは「未認識の発話」として人に回す                            |
| 言い直しの判定   | `claude -p`（レクチャー単位）  | ファイルをまたいだ判断ができ、費用がかからない。代わりに出力は確定的でなく、利用上限の影響を受ける            |
| ジョブの実行     | worker プロセス 1 つで直列     | 単純でメモリ使用量が読める。代わりに大量に投入すると待ち時間が長い                                            |
| テキスト編集     | 自前の読み取り専用トークン表示 | 必要なのは選択と削除だけなので、エディタフレームワークは過剰。文字の修正は将来                                |
| 永続化           | SQLite + ファイル              | 標準ライブラリだけで済み、ジョブ表の排他も扱える                                                              |

## 6. テスト戦略

| 種類        | 対象                                                                                              | 方法                                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| unit        | domain（残す区間・余白・フレームへの丸め・時刻の変換・候補の引き継ぎ）、pipeline の各段、services | 偽の ports を注入。外部ツールは呼ばない                                                                                                              |
| integration | adapters（ffmpeg、SQLite、XML の生成）                                                            | ffmpeg の `lavfi` で生成した数秒の小さな素材（可変フレームレートを含む）を使う。ML と `claude -p` の adapter は `@pytest.mark.ml` で既定では除外する |
| E2E         | 投入 → 解析 → 編集 → 書き出し                                                                     | Playwright。環境変数で ML と判定を偽の実装に差し替え、結果を決定的にする                                                                             |
| 精度評価    | 言い直しの判定                                                                                    | `vidcut eval judge` で `sample-chunks.json` を判定し、正解データと比べて適合率・再現率を出す（PRD 3-1）。`claude` を呼ぶので通常のテストには含めない |

### 実装前のスパイク（検証）

実装計画の最初に、以下を検証素材（`~/Desktop/s05-12sample.mov`）で確かめ、ADR-002・ADR-003 を確定させる。

1. **S-1 Premiere XML**: 中間素材を参照した XML と、元素材を参照した XML を Premiere で読み込み、音ズレとフレーム欠けを比べる（D-3）
