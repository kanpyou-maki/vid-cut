# 受け入れチェックの記録（M8）

[PRD](../prd.md) 3-2 の受け入れ基準を、実際の撮影素材 3 本で確かめた記録。判定するのは制作者本人。
計画は [PLAN-20261003-mvp-implementation](../exec-plans/active/PLAN-20261003-mvp-implementation.md) の M8。

- **素材**: `~/Desktop/forTest01.mov`・`forTest02.mov`・`forTest03.mov`（各約 2 分。無音・フィラー・言い直しあり）
- **合格基準**: 誤削除は素材 1 本あたり 2 件以下、書き出しの音ズレ・フレーム欠けは 0 件。削除漏れと作業時間は記録のみ
- **状態**: 実施済み（2026-10-05。3 本とも合格）。見つかった点の原因と対応は、下の「調べたこと」

## 手順

1. `uv run --directory backend vidcut serve` で起動し、素材一覧から 3 本を投入する。投入した時刻を控える
2. 「編集待ち」になったら、1 本ずつ編集画面を開く。文字起こしを読み、プレビューで聞いて、次の 2 つを直す
   - **誤削除**（必要な発話が消えている）: 削除済みの部分をクリックして戻す。言い直し・言い間違い・雑音・フィラーのどれだったかは、色と理由の表示で分かる
   - **削除漏れ**（消すべきなのに残っている）: 文字を選んで Delete で削除する。文字起こしに出ていない音（書き起こされなかったフィラーなど）は、下の表の「気づいたこと」に時刻を書く
3. Premiere XML を書き出し、Premiere Pro で読み込む。最初・中ほど・最後のつなぎ目で、音ズレとフレーム欠けがないかを見る
4. 終わった時刻を控える。下の表を埋める

件数の下書きは、編集状態から集計できる（戻した候補 ≒ 誤削除、手動の削除 ≒ 削除漏れ）。Claude Code に「受け入れの件数を集計して」と頼むと、ワークスペースの写しを読んで表の下書きを作る（実データは書き換えない）。
戻した理由が「誤削除ではなく、好みで残した」などの場合は、表で直す。

### 調べたこと（2026-10-05）

- **チェックのときの画面は、古いビルドだった**: `frontend/dist` が PR #20・#21 の前のビルドのままで、「間の設定」がなく、プレビューは文末のあとの余白も 250ms で計算していた（書き出しは 500ms）。
  `npm --prefix frontend run build` のあとは「間の設定」が出て、動作を確認済み（制作者）。「間が短い」という印象は、古い値でのもの。値は「間の設定」で変える
- **フィラーと判定されているのに消えない（4 件）**: 位置合わせが、伸ばした声にごく短い時刻しか付けず、削除区間がその時刻のままだった
  （forTest01 0:55「えー」161ms / 次の語まで約 600ms、forTest02 1:10「あのー」161ms / 約 620ms、forTest02 1:20「えー」41ms / 約 280ms、forTest03 1:26「うーん」769ms / 約 1,230ms）。
  音量では、声は次の語の直前まで続いていた → 削除区間を、前の語の終わりから次の語の頭の手前まで広げた（M8 の `fix/m8-filler-span`）。
  直したあとの長さ: 553ms・1,236ms（「まあ、あのー」）・232ms・1,184ms。登録済みの録画には、`vidcut reanalyze --wait` で当て直す
- **「まあ、あのー」の「まあ」**: 「まあ」は内容語にもなるので単独では消さない → フィラーと続いているときは、まとめて消す（同じ PR）
- **forTest03 1:20 の「あー」**: 文字起こしは「次の三にはあー」で、句読点も間もなく、規則から外れていた（下調べの一時ワークスペースでは「次の3には、あー、えーと。」と書き起こされていた。文字起こしは実行ごとに少し違う）
  → チャンクの終わりまで続くフィラーは、前が区切れていなくても消す（同じ PR。フィラーのない検証素材では、誤検出 0 件のまま）
- **直したあとのフィラーの候補**（実データの写しで確認）: forTest01 は 4 → 5 件、forTest02 は 2 → 5 件、forTest03 は 5 → 7 件。増えたぶんは、読点で区切られたもの・続いたもの・チャンクの終わりのもの
- **「メールヘッダー」の言い直し**: 「…クロスサイトスクリプティングとメールヘッダー。」の末尾だけが言い直しの前の版。判定はチャンク（無音で区切った発話）単位なので、チャンクの一部だけの言い直しは消せない（制限。文字を選んで削除する）
- **「終了します」の誤削除**: 判定が「録画終了を告げる独り言」として雑音にした。1 件の例に合わせて指示文を変えると、ほかの素材で悪化しうるので、直さず記録だけにする（制作者と合意）
- **シークバーで文字起こしが動かない**: 文字起こしの追従は再生中だけの作りだった → 止めたままのシークでも追従させる（M8 の `fix/m8-acceptance`）

## 追加の確認（2026-10-05。実装者）

受け入れの素材（各約 2 分）では確かめられないものを、別に確かめた。どちらも一時フォルダで行い、実データには触れていない。使ったスクリプトは使い捨て（コミットしていない）。

### 長いレクチャー（人工データ。約 2 時間）

13 秒の台本を 554 回繰り返した素材（7,202 秒）を ffmpeg で作り、偽の文字起こしと偽の判定で解析して、実物の Chrome（ヘッドレス）で測った。
チャンク 2,216 個、トークン 33,240 個、無音 2,217 個、削除候補 3,325 件（無音・フィラー・言い直し）、カット後の長さ 1 時間 4 分。

| 操作                                              | 結果                                                                         |
| ------------------------------------------------- | ---------------------------------------------------------------------------- |
| 編集画面を開く（クリック → 文字起こしが出る）     | 約 0.7 秒（レクチャーの詳細は 7.7MB で 0.3 秒、ピーク値は 3.6MB）            |
| 文字を選んで削除（Delete → 表示）                 | 70〜90ms                                                                     |
| 取り消し（⌘Z）                                    | 約 65ms                                                                      |
| 候補を戻す（クリック）                            | 約 80ms                                                                      |
| 間の設定を変える（入力 → カット後の長さが変わる） | 約 65ms                                                                      |
| 再生（5 秒）、再生位置のバーでの移動              | 50ms を超える処理なし                                                        |
| 波形を「全体」にする・「全体」から拡大に戻す      | **約 3 秒固まる**（区間の要素が 13 個 → 3,326 個になる。その 1 回だけ）      |
| 波形を「全体」にしたままの編集・間の設定・再生    | 上と同じ（80ms 以下）                                                        |
| 書き出しの計画（残す区間の計算。backend）         | 0.18 秒（クリップ 1,662 個）                                                 |
| 言い直しの判定の窓分割（300 チャンクごと）        | 9 回に分かれ、554 件の言い直しをすべて拾った（偽の判定。重なりの統合の確認） |
| JS のヒープ                                       | 75〜100MB                                                                    |

- 重いのは、2 時間のレクチャーで波形を「全体」に切り替えるときだけ（約 3 秒）。編集・再生・保存は、長さによらず軽い。編集のたびに文字起こし全体を描き直しているが、3 万トークンでも 100ms を切る
- 解析（偽の ML。proxy 動画の再エンコードなど）は 2 時間の素材で約 2 分半。実物の ML の時間は含まない
- 窓分割は、偽の判定での確認（窓の端で取りこぼしや重複がないこと）。実物の言語モデルで、窓をまたぐ言い直しをどれだけ拾えるかは、確かめていない

### 複数の録画ファイルのレクチャー（実素材）

実データの写しで、forTest01 と forTest02 を 1 つのレクチャーにまとめた。

- まとめると、言い直しの判定がやり直される（実物の `claude -p` を 1 回。約 34 秒）。削除は 38 件 + 35 件で、まとめる前と同じ件数。戻していた候補（「終了します」）は引き継がれ、引き継げなかった候補は 0 件
- 編集画面（実物の Chrome）: トークン 1,240 個、カット後の長さ 2 分 31 秒。2 本目の文字をクリックすると 2 本目の動画に切り替わり、そのまま再生できる。再生位置のバーを先頭へ戻すと 1 本目に戻る。
  波形は 1 本につながる（2 本目の名前は、その位置までスクロールすると出る。見えていない区間の要素は作られない）。コンソールの失敗・読み込みの失敗なし

## 下調べ（2026-10-04。自動の結果だけ。正しいかどうかは未判定）
